# 8080_8443_Web_Alt

## 발견 시 판단

현재 명령 실행 호스트에서 `<TARGET>:<PORT>`의 HTTP/HTTPS 응답을 받을 수 있고, 아직 관리 계정이나 관리 기능 권한은 확인하지 않은 상태에서 시작한다. [[80_443_HTTP_HTTPS]]의 헤더·TLS·vhost·경로 흐름을 따른 뒤 80/443과 다른 애플리케이션, 관리 콘솔, Application Programming Interface(API) 문서, debug 기능과 프록시 동작처럼 대체 포트에서 생기는 차이만 가른다.

**첫 화면 상태:** 지금 가능한 일은 포트별 애플리케이션·Host/SNI·관리 기능의 차이를 확인하는 것이다. 성공하면 검증할 관리 경로·API·인증 경계를 얻는다. 응답 실패는 HTTP/HTTPS scheme·Host·SNI와 제품 기본 경로를, 로그인 거부는 계정 형식·잠금 정책·관리 role을, 프록시 후보 실패는 실제 목적지 허용 목록과 요청 형식을 확인한다. 관리 콘솔·PUT 메서드·프록시처럼 보이는 응답만으로 로그인·파일 쓰기·내부 접근은 확정되지 않는다.

## 서비스 고유 확인

| 우선순위 | 확인할 것 | 명령·도구 | 다음 판단 |
|---|---|---|---|
| 1 | 80/443과 포트별 애플리케이션 차이 | `curl -skI http://<TARGET>:<PORT>/` | title, Server, Location, 쿠키와 Host 처리 차이를 [[80_443_HTTP_HTTPS]] 응답과 비교한다. |
| 2 | 관리·API·debug 기능 | `gobuster dir -u http://<TARGET>:<PORT>/ -w <WORDLIST>` | admin, manager, docs, swagger, api, actuator, debug처럼 대체 포트 고유 경로를 확인한다. |
| 3 | 프록시 또는 별도 관리 호스트 | `curl -i -X OPTIONS http://<TARGET>:<PORT>/`, `openssl s_client -connect <TARGET>:<PORT> -servername <HOST>` | 허용 메서드, SNI와 proxy 처리 차이를 실제 쓰기·내부 접근과 구분한다. |

**출력 해석 경계:** 포트별 header, title, TLS 인증서의 차이는 별도 endpoint 또는 vhost 후보를 확정하지만 별도 서버·관리자 권한을 확정하지 않는다. Swagger, actuator, debug의 응답은 공개된 메타데이터·경로만 확정하며 민감 정보의 유효성은 수동 요청으로 다시 확인한다. OPTIONS의 `PUT` 또는 프록시 형태 응답은 허용 메서드·동작 후보일 뿐 원격 파일 쓰기·내부 네트워크 접근을 증명하지 않는다.

## 서비스 고유 주의 사항

- 특정 Host 헤더·SNI·경로에서만 응답할 수 있고 404도 제품 기본 경로 차이일 수 있다.
- 관리 콘솔은 제품명·버전과 계정 잠금 정책을 확인한 뒤 낮은 빈도로 credential을 검증한다.
- OPTIONS의 PUT/WebDAV 표시는 실제 파일 쓰기나 실행 성공을 뜻하지 않는다.
- `/certsrv` 노출은 단독 취약점이 아니며 NTLM relay 조건, template와 발급 주체 권한을 함께 확인한다.
