# Linux 권한 상승 열거

## 한 줄 판단

대상 Linux 호스트에서 현재 사용자 셸과 기본 명령 실행 권한이 있으면, 그 호스트의 OS·계정·sudo·SUID·cron·파일 권한·자격 증명 노출을 조회하여 현재 계정이 실제로 제어할 수 있는 root 권한 상승 후보를 고른다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | 대상 Linux 호스트의 대화형 또는 명령 실행 가능한 셸 | `id`, `hostname`이 대상에서 실행되는지 확인 | 불안정한 셸이면 기본 명령 실행과 출력 회수부터 안정화 |
| 현재 계정 또는 인증 수단 | 셸 프로세스가 사용하는 현재 Linux 사용자·그룹 | `id`와 `whoami` 확인 | 웹 서비스 계정·SSH 계정 등 셸의 실제 실행 주체를 다시 확인 |
| 현재 권한 | 기본 명령 실행 및 허용된 시스템 정보·파일 읽기 | `uname`, `/etc/os-release`, `sudo -l`과 디렉터리 조회 결과 확인 | permission denied를 숨기지 말고 접근 가능한 경로와 그룹 권한부터 열거 |
| 공격 대상의 조건 | 현재 셸이 열린 로컬 Linux 호스트의 권한 상승 경로 확인 | hostname, OS·kernel·아키텍처와 실행 환경 확인 | container·chroot·호스트 컨텍스트가 섞이지 않았는지 확인 |
| 필요한 파일·목록·주소 | 기본 열거에는 추가 파일 불필요, 자동 열거에는 `linpeas.sh`·`LinEnum.sh` 필요 | 로컬 파일의 출처와 실행 가능 여부 확인 | 전송·실행이 제한되면 수동 명령만 사용 |

## 실행

### 기본 정보

현재 셸 계정, 호스트와 OS·kernel을 식별하고 해당 계정에 허용된 sudo 명령을 확인한다.

이 블록은 대상 Linux 호스트의 현재 셸에서 실행하며 `id`·`hostname`·`uname` 출력은 이후 후보의 계정·호스트·kernel context로 재사용한다.

```bash
id
hostname
uname -a
cat /etc/os-release
sudo -l
```

확인할 출력:

- 사용자/그룹, kernel, sudo 가능 명령.
- `sudo -l`의 비밀번호 요구·허용·거부 출력을 구분한다. 명령 부재나 거부는 SUID·cron·파일 권한 경로가 없다는 뜻이 아니다.

### 주요 권한 단서

root 등 더 높은 권한으로 실행될 파일과 현재 계정이 쓸 수 있는 경로가 실제로 연결되는지 확인한다.

```bash
find / -perm -4000 -type f 2>/dev/null
find / -writable -type d 2>/dev/null | head
test -w /etc/passwd && ls -l /etc/passwd
cat /etc/crontab
ls -la /etc/cron.d /etc/cron.hourly /etc/cron.daily 2>/dev/null
```

확인할 출력:

- SUID binary, writable script/path, writable `/etc/passwd`, cron 실행 사용자.
- `find`의 숨긴 permission denied 때문에 결과가 일부일 수 있다. 발견한 파일은 소유자·mode·실제 실행 경로를 다시 확인하고, writable 디렉터리만으로 높은 권한 실행을 단정하지 않는다.

### 자동 열거

수동 결과를 보강할 수 있을 때만 현재 호스트에서 스크립트를 실행하고 각 단서를 작은 명령으로 재현한다.

`./linpeas.sh`와 `./LinEnum.sh`는 현재 대상 셸의 작업 디렉터리에 이미 있는 파일 경로를 뜻한다. 강조 출력은 후보일 뿐 root 실행·파일 읽기·취약성의 확정 근거가 아니며, 실행 주체·소유자·제어 지점을 바로 위 수동 명령으로 재확인한다.

```bash
./linpeas.sh
./LinEnum.sh
```

확인할 출력:

- 빨간색/강조 결과를 그대로 믿지 말고 권한 조건과 재현 명령을 확인한다.
- 실행이 차단되면 파일 전송·실행 권한, mount 옵션, 보안 제품과 셸 안정성을 구분한 뒤 수동 열거로 전환한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| root로 실행 가능한 sudo, SUID 또는 cron 경로가 발견된다. | 실행 주체와 제어 지점 확인 | 권한 상승 단서 | 유형에 따라 [[sudo 권한 오남용]], [[SUID GTFOBins 권한 상승]], [[Cron 권한 상승]]으로 분기 |
| 현재 사용자로 `/etc/passwd` 내용을 수정할 수 있다. | 계정 인증 상태를 바꿀 수 있는 고영향 파일 권한 오류 | 권한 상승 후보 | [[쓰기 가능한 passwd 빈 비밀번호 권한 상승]]에서 PAM 수락 조건·기준선·즉시 복구를 먼저 확인 |
| 읽을 수 있는 비밀번호, SSH key 또는 DB credential이 나온다. | 재사용 가능한 자격 증명 단서 확인 | 자격 증명 단서 | 소유자와 대상 서비스를 확인하고 해당 인증 기법으로 전달 |
| kernel/software 버전과 exploit 전제 조건이 모두 맞는다. | 로컬 exploit 후보 확인 | 권한 상승 후보 | [[Kernel Exploit 후보 검증]]에서 빌드, 아키텍처와 보호 설정 재확인 |
| 자동 스크립트 차단 | AV/모니터링/권한 | 시작 상태 유지 | 수동 열거, 작은 명령 단위 |
| 단서 많음 | 노이즈 | 시작 상태 유지 | root 실행/쓰기 가능/credential 포함 결과만 우선 |
| exploit 후보 위험 | kernel crash 가능 | 시작 상태 유지 | 다른 경로를 우선하고 빌드·아키텍처·보호 설정 재확인 |

## 확인할 출력과 권한

- 판정 기준: `id`, `sudo -l`, SUID·cron·쓰기 권한의 실제 소유자와 실행 사용자를 확인한다.
- 열거 결과는 현재 계정이 읽거나 관찰한 설정과 파일만 확정한다. root 코드 실행, 자격 증명의 유효성, kernel exploit 적용 가능성은 대응 기법에서 별도로 검증한다.
