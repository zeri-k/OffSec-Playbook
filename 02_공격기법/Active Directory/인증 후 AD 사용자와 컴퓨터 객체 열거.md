# 인증 후 AD 사용자와 컴퓨터 객체 열거

## 한 줄 판단

도메인·DC와 사용할 AD 계정을 확인했으면 필요한 결과가 계정 속성인지 호스트 목록인지 먼저 구분하고 사용자 객체와 컴퓨터 객체를 각각 독립된 열거 문서에서 확인한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 미충족 시 다음 확인 |
|---|---|---|
| 현재 AD 계정과 도메인 | 어느 도메인의 어떤 계정으로 조회하는지 확인 | [[AD 도메인 컨텍스트 기본 확인]] |
| 필요한 결과 | 사용자 속성 또는 컴퓨터·FQDN 후보 중 먼저 필요한 결과 선택 | 현재 목표와 다음 기법의 입력을 다시 확인 |

## 실행

이 문서는 선택 순서만 제공한다. 필터·옵션·OS별 문법과 출력 해석은 세부 기법에서 한 번만 관리한다.

| 먼저 필요한 결과 | 실행할 기법 | 확인할 결과 | 다음 판단 |
|---|---|---|---|
| 계정명·DN·활성 상태·SPN·위험 속성 | [[AD 사용자 객체 열거]] | 사용자 객체와 필요한 속성 | 그룹·SPN·계정 위험 속성 열거 |
| 컴퓨터명·FQDN·운영체제·마지막 로그온 단서 | [[AD 컴퓨터 객체 열거]] | 컴퓨터 객체와 서비스 후보 | DNS·서비스·세션·원격 접근 확인 |
| Password Spraying 후보 | [[AD 사용자 객체 열거]]에서 `samaccountname` 목록 생성 | 빈값·중복이 제거된 후보 목록 | [[AD 비밀번호 정책 열거 및 조회]] 후 [[내부 AD Password Spraying]] |

대표 시작 명령은 현재 AD 컨텍스트가 실제로 맞는지 확인하는 용도다. 결과가 없으면 객체 열거 명령을 반복하기 전에 도메인·Base DN·현재 계정의 읽기 범위를 다시 확인한다.

```powershell
Get-ADDomain
```

`DNSRoot`와 `DomainMode`가 기대한 도메인을 가리키면 필요한 결과의 세부 기법 하나만 선택한다. 인증 성공은 객체 읽기 권한이나 원격 로그온 권한을 뜻하지 않는다.

## 관찰과 상태 전환

`Get-ADDomain`이 실패하면 사용자·컴퓨터 객체 열거를 반복하지 않고 도메인·DC·현재 계정의 LDAP 접근을 다시 확인한다. 성공하면 위 실행 표에서 현재 필요한 결과 하나만 선택하며, `samaccountname` 목록은 잠금 정책과 계정별 적용 정책을 확인한 뒤에만 [[내부 AD Password Spraying]] 입력 후보로 사용한다.

## 확인할 출력과 권한

- 사용자 객체 반환과 컴퓨터 객체 반환은 독립된 결과다.
- 컴퓨터 객체는 현재 활성 호스트를, 사용자 객체는 비밀번호 유효성이나 현재 권한을 뜻하지 않는다.
- Password Spraying 전에는 disabled 상태, `badpwdcount`, 도메인 기본 정책과 Fine-Grained Password Policy를 확인하고 단일 비밀번호 후보·최대 시도 횟수·간격을 정한다.
