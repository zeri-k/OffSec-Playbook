# FTP Bounce

## 한 줄 판단

실행 호스트에서 로그인 가능한 FTP 서버 21/TCP에 닿고 서버가 `PORT` 명령의 제3자 연결을 허용하면, FTP 서버 기준으로 지정한 내부 대상 포트의 TCP 도달성을 확인해 후속 서비스 검증 후보를 얻는다.

## 사용할 때

- 현재 보유 정보: FTP 서버 주소, anonymous 또는 유효한 FTP 계정, 확인할 내부 IP와 소수의 포트 후보가 있다.
- 명령 실행 위치와 도달 대상: `nmap -b`를 실행할 호스트에서 FTP 서버 21/TCP에 접속할 수 있다. 실행 호스트가 내부 대상에 직접 닿을 필요는 없지만 FTP 서버에는 내부 대상 경로가 있어야 한다.
- 현재 계정과 권한: FTP 로그인 계정이 세션을 만들고 서버가 제3자 주소를 지정한 `PORT` 데이터 연결을 허용해야 한다. FTP 서버 운영체제 권한이나 내부 서비스 계정은 확보한 상태가 아니다.
- 지금 가능한 행동과 결과: 외부에서 직접 접근되지 않는 내부 대상에 대해 FTP 서버가 특정 TCP 포트로 연결 가능한지 확인할 수 있으며, 이는 내부 서비스의 종류·취약성·인증 가능성을 확정하지 않는다.

## 확인할 단서

| 단서 | 의미 | 다음 행동 |
|---|---|---|
| `Resolved FTP bounce attack proxy` | nmap이 FTP proxy로 인식 | 내부 포트 범위를 제한해 확인 |
| 특정 내부 포트 open | FTP 서버에서 해당 포트로 연결 가능 | 해당 서비스 공격면 검토 |
| `bounce attack not allowed` | 서버가 보호됨 | 일반 FTP 파일 수집으로 전환 |

## 실행

1. FTP 로그인 가능 여부를 확인한다.
2. 내부 대상 IP와 우선 포트를 정한다.
3. `nmap -b`로 FTP bounce 가능성을 작게 검증한다.
4. 열린 포트가 나오면 해당 서비스 문서로 이동한다.

### 명령과 확인할 출력

#### anonymous FTP bounce 확인

```bash
nmap -Pn -v -b anonymous:anonymous@<FTP_SERVER>:21 <INTERNAL_TARGET> -p <PORTS>
```

확인할 출력:

- `Resolved FTP bounce attack proxy`
- 내부 대상의 `open`, `closed`, `filtered` 포트 상태
- `bounce attack not allowed`이면 서버가 제3자 연결을 거부한 것이므로 FTP 로그인 성공과 분리해 판정한다. 인증 오류는 계정·비밀번호와 FTP 서버 주소를 먼저 확인한다.

#### 계정 기반 FTP bounce 확인

```bash
nmap -Pn -v -b <USER>:<PASSWORD>@<FTP_SERVER>:21 <INTERNAL_TARGET> -p 21,22,80,445,3389
```

확인할 출력:

- FTP 서버가 내부 대상의 특정 포트에 연결할 수 있는지 확인한다.
- 모두 `filtered`이거나 timeout이면 내부 대상·포트, FTP 서버의 라우팅과 중간 방화벽을 확인한다. 이 결과만으로 내부 호스트 부재를 확정하지 않는다.

## 확인할 출력과 권한

- 판정 기준: `Resolved FTP bounce attack proxy`와 내부 포트 상태를 함께 확인하고, FTP 로그인 성공만으로 bounce 성공을 판정하지 않는다.
- `open`은 FTP 서버 기준의 해당 TCP 포트 연결 단서다. 실행 호스트의 직접 접근, 범용 프록시·셸 확보, 서비스 종류와 인증 권한은 확정하지 않는다.
- 권한 구분: 인증 전·익명·유효 계정 상태를 구분하고, 서비스 응답만으로 실제 권한을 추정하지 않는다.
