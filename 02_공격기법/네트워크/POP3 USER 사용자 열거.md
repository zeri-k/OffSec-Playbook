# POP3 USER 사용자 열거

## 한 줄 판단

POP3·POP3S에 닿는 실행 호스트와 사용자명 후보가 있으면, 인증 전 `USER` 응답을 존재하지 않을 기준 사용자와 반복 비교하여 서버가 구분해 노출하는 메일 계정 후보만 수집하고 실제 비밀번호 인증·메일함 읽기 권한과 분리한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | 도구 실행 호스트에서 POP3 110/TCP 또는 POP3S 995/TCP에 도달 | `+OK` 서비스 배너 또는 TLS 협상 후 배너 확인 | 대상 주소·포트, 방화벽, implicit TLS와 POP3 `STLS` 지원 여부 확인 |
| 현재 계정 또는 인증 수단 | 인증 전 열거이므로 계정 불필요 | 연결 직후 `USER` 명령을 보낼 수 있는지 확인 | 서버가 선행 TLS나 다른 인증 흐름을 요구하는지 확인 |
| 현재 권한 | 서버가 인증 전 `USER` 명령과 비교 가능한 응답을 허용 | 기준 사용자와 후보 사용자에 대한 응답 수신 | 연결 종료·rate limit·동일 응답 정책이면 대체 사용자 수집 경로 사용 |
| 공격 대상의 조건 | POP3·POP3S가 실제로 동작하며 `USER` 단계 응답을 제공 | 배너와 `+OK`·`-ERR` 응답 확인 | IMAP·SMTP 등 다른 메일 서비스와 포트를 혼동하지 않았는지 확인 |
| 필요한 파일·목록·주소 | 대상 주소, 후보 목록, 존재하지 않을 기준 사용자명 | 계정 형식과 동일한 비교 기준 준비 | username·전체 이메일 주소 형식을 각각 비교 |

## 확인할 단서

| 단서 | 의미 | 다음 행동 |
|---|---|---|
| `USER <USER>` 뒤 `+OK` | 사용자 존재 가능성 | `PASS` 검증은 잠금 정책을 고려해 별도 수행 |
| `USER <USER>` 뒤 `-ERR` | 사용자 부재 또는 정책상 거부 | 다른 사용자 형식 확인 |
| 모든 사용자가 같은 응답 | 사용자 열거 차단 가능성 | SMTP/웹/OSINT 기반 사용자 수집으로 전환 |

## 실행

`<TARGET>`은 POP3 서버 주소(가상 예시 `mail.example.test`), `<USER>`는 확인할 사용자명 또는 전체 메일 주소, `<BASELINE_USER>`는 같은 형식의 명백히 존재하지 않는 비교값이다. `<POP3S_PORT>`는 implicit TLS 포트(보통 `995`)이며, 아래 `telnet`·`openssl` 명령은 대상에 도달하는 공격 호스트에서 후보와 기준값을 같은 연결 방식으로 각각 실행한다.

1. POP3/POP3S 배너와 TLS 여부를 확인한다.
2. 명백히 존재하지 않는 사용자와 후보 사용자의 `USER` 응답을 같은 연결 방식의 새 세션에서 각각 비교한다.
3. 응답 차이가 있을 때만 후보 목록을 확장한다.
4. 유효 후보는 [[원격 비밀번호 공격]] 또는 [[IMAP POP3 메일함 수집]]으로 넘긴다.

### 명령과 확인할 출력

#### POP3 평문 확인

```bash
telnet <TARGET> 110
USER definitely-not-a-user
USER <USER>
QUIT
```

확인할 출력:

- `+OK`와 `-ERR` 응답 차이가 사용자 존재 여부 단서가 되는지 확인한다.
- 모든 입력이 같은 응답이면 존재 여부를 구분할 수 없다. 연결 종료나 `-ERR`가 명령 형식 때문인지 확인한 뒤 다른 서비스의 사용자 수집으로 전환한다.

#### POP3S 확인

```bash
openssl s_client -crlf -connect <POP3_HOST>:995 -servername <POP3_HOST>
USER <USER>
QUIT
```

확인할 출력:

- TLS 연결 후 POP3 명령에 대한 응답이 평문 POP3와 같은 방식으로 구분되는지 확인한다.
- TLS 협상 실패는 인증 결과가 아니므로 995/TCP, 인증서·프로토콜과 STARTTLS 지원 여부를 먼저 확인한다.

## 확인할 출력과 권한

- 판정 기준: 가짜 사용자 기준값과 후보 사용자의 `+OK`·`-ERR` 차이가 반복되는지 확인한다.
- 반복되는 응답 차이는 서버가 후보를 다르게 처리한다는 사실만 확정한다. `+OK` 하나만으로 사용자 존재를 확정하지 않으며, 비밀번호·인증 성공·메일함 접근은 전혀 확정하지 않는다.
- 권한 구분: 인증 전·익명·유효 계정 상태를 구분하고, 서비스 응답만으로 실제 권한을 추정하지 않는다.
