# SMB 쓰기 가능한 공유 검증

## 한 줄 판단

SMB 클라이언트를 실행할 수 있는 호스트에서 Null·Guest 또는 유효 계정으로 대상 SMB 공유에 도달해 식별 가능한 테스트 파일을 생성·조회·삭제하고, 현재 인증 Identity의 실제 경로별 권한과 파일을 소비하는 실행 주체의 존재를 별도로 확인한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | SMB 클라이언트가 있는 호스트에서 대상 445/TCP와 공유에 도달 가능 | 대상 연결과 공유 목록 응답 확인 | 이름 해석, 445/TCP 경로와 공유명을 재확인 |
| 현재 계정 또는 인증 수단 | `WRITE` 표시를 얻은 것과 같은 Null·Guest·도메인·로컬 계정 컨텍스트 | 도구 출력의 로그인 상태, 도메인과 사용자명 확인 | 다른 Identity의 권한 결과와 섞지 말고 인증 형식을 바로잡음 |
| 현재 권한 | 대상 공유 또는 선택한 하위 디렉터리에서 파일 생성이 허용될 가능성 | `smbmap`, `netexec --shares`의 `WRITE` 표시 | 표시는 후보로만 유지하고 하위 경로별 실제 업로드 결과 확인 |
| 공격 대상의 조건 | 검증할 정확한 공유명과 하위 경로 식별 | 공유 내용과 경로 의미 확인 | 웹 루트·배포·logon script·scheduled task 경로 여부를 별도 조사 |
| 필요한 파일과 복구 경로 | 기존 파일과 겹치지 않는 식별 가능한 파일 및 동일 파일 제거 방법 | 로컬 파일명, 원격 생성 위치와 삭제 권한 계획 확인 | 서버 측 제거 경로가 없으면 proof 파일을 만들지 않음 |

## 실행

`<TARGET>`은 SMB 서버 주소(가상 예시 `192.0.2.45`), `<SHARE>`·`<REMOTE_DIRECTORY>`는 실제 WRITE 후보인 공유·하위 경로다. `<REQUESTER>`의 인증 자료는 쓰기를 검증할 SMB session용이며 `<PROOF>`는 공격 호스트에서 새로 만든 basename이다. 아래 명령은 공격 호스트에서 실행하고 같은 proof 이름으로 생성·조회·삭제를 이어서 확인한다.

### 권한 확인

먼저 현재 인증 Identity가 성공했는지 확인한 뒤, 같은 Identity에 표시되는 공유별 권한을 기록한다.

```bash
smbmap -H <TARGET> -u <USER> -p '<PASSWORD>'
netexec smb <TARGET> -u <USER> -p '<PASSWORD>' --shares
```

확인할 출력:

- share별 `READ, WRITE`.
- 로그인 성공과 `WRITE` 표시는 실제 하위 경로 파일 생성 성공과 별도 상태다.

### 업로드/삭제 확인

검증할 공유와 하위 경로에서만 고유한 테스트 파일을 업로드하고, 같은 인증 컨텍스트에서 조회와 삭제 가능 여부를 각각 확인한다. 아래 명령은 같은 shell에서 실행하며 `$PROOF` 값을 작업 기록에 남긴다.

```bash
PROOF="smb-proof-$(date -u +%Y%m%dT%H%M%SZ)-$$.txt"
printf 'SMB write verification: %s\n' "$PROOF" > "$PROOF"
smbclient //<TARGET>/<SHARE> -U '<USER>%<PASSWORD>' -c "cd <REMOTE_DIRECTORY>; put $PROOF $PROOF; ls $PROOF; del $PROOF; ls $PROOF"
```

확인할 출력:

- `putting file`, 첫 `ls`의 정확한 `$PROOF`, `del` 성공과 마지막 `ls`의 `NT_STATUS_OBJECT_NAME_NOT_FOUND`를 단계별로 확인한다.
- 마지막 조회 실패는 삭제 완료를 확인하는 예상 결과다. `del` 자체가 거부됐거나 연결이 끊겼다면 원격 정리가 완료됐다고 기록하지 않는다.

| 관찰 | 판단 | 결과 상태 | 다음 행동 |

| 쓰기 검증 파일의 업로드와 조회가 가능하다. | 현재 인증 Identity로 해당 경로의 파일 생성과 조회 가능 | 검증된 파일 쓰기 | 같은 경로의 삭제와 덮어쓰기는 별도 권한으로 확인 |

| share에 `WRITE`가 표시되지만 업로드 실패 | 공유 표시와 선택한 경로의 실제 ACL 또는 인증 컨텍스트가 다를 수 있음 | 쓰기 권한 미확인 | 인증 Identity, 공유명과 하위 디렉터리별 권한 확인 |
| 업로드는 가능하지만 조회·소비 주체가 미확인 | 파일 생성 권한만 확인되고 읽기·실행 영향은 미확정 | 제한된 파일 쓰기 | 파일 조회 권한과 서버 측 소비 경로를 별도로 확인 |
| 삭제 불가 | 쓰기와 삭제 권한 비대칭 | 파일 쓰기 | 생성된 쓰기 검증 파일의 위치와 이름 확인 |
| SMB 인증 또는 공유 연결 실패 | 현재 계정, 인증 형식, 네트워크 경로 또는 공유명이 미확정 | 검증 시작 전 상태 | Null·Guest·도메인·로컬 인증을 구분하고 445/TCP와 공유명을 재확인 |

## 확인할 출력과 권한

- share의 `WRITE` 표시는 현재 인증 Identity에 대한 도구의 권한 해석이며 실제 하위 경로의 생성 성공을 확정하지 않는다.
- 업로드 성공은 해당 경로의 파일 생성만 확정한다. 기존 파일 덮어쓰기, 삭제, 서버 측 실행과 그 실행 주체의 권한은 각각 별도 결과다.
- 웹 루트·배포·logon script·scheduled task처럼 보이는 이름만으로 실행을 단정하지 않고 실제 소비 주체와 trigger를 확인한다.

## 변경 영향과 복구

위 실행은 기존 파일과 겹치지 않는 `$PROOF` 하나만 업로드하고 같은 명령 흐름에서 정확한 이름만 삭제한다. 원격 삭제가 확인된 뒤 공격 호스트의 로컬 proof를 제거한다.

```bash
rm -f -- "$PROOF"
test ! -e "$PROOF" && echo 'local proof removed'
```

확인할 출력:

- 삭제 성공 뒤 `$PROOF`가 원격 목록에 더 이상 나타나지 않는다.
- 삭제 권한이 없으면 업로드 전에 별도 서버 측 제거 경로를 확인하고, 확인할 수 없다면 proof 파일을 만들지 않는다.
