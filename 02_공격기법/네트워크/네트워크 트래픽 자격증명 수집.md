# 네트워크 트래픽 자격증명 수집

## 한 줄 판단

pcap을 읽을 수 있는 분석 호스트나 대상 인증 트래픽을 관찰할 수 있는 캡처 호스트가 있으면 평문 사용자명·비밀번호, NetNTLM challenge-response, Kerberos principal·ticket·AS-REP/TGS 암호문을 형식별로 추출해 오프라인 비밀번호 복구·relay·서비스 인증 검증으로 분기한다.

## 사용할 때

- 현재 보유 정보: 실습 pcap 파일 또는 대상 인증 트래픽을 볼 수 있는 인터페이스와 분석할 호스트·시간·프로토콜 단서를 확보했다.
- 명령 실행 위치와 도달성: 오프라인 분석은 pcap이 저장된 분석 호스트에서, 라이브 캡처는 대상 트래픽이 실제로 지나가는 캡처 호스트의 인터페이스에서 수행한다.
- 현재 가능한 행동과 결과: FTP·HTTP·SMTP·POP3·IMAP·SNMP의 평문 인증, Windows NetNTLM challenge-response와 Kerberos ticket·AS-REP/TGS hash를 찾아 값의 종류에 맞게 서비스 검증·크래킹·relay 가능성을 판단한다.

## 실행

1. 분석 호스트와 pcap 경로 또는 라이브 캡처 인터페이스, 대상 호스트·시간 범위를 확인한다.
2. PCredz의 버전·`-o` 지원을 확인하고 민감 로그를 구분할 고유 출력 디렉터리를 만든 뒤 프로토콜 필터로 인증 교환을 좁힌다.
3. 평문 비밀번호, NetNTLM challenge-response, Kerberos ticket·AS-REP/TGS hash와 단순 사용자명·호스트 단서를 구분한다.
4. 출력이 없으면 암호화·캡처 지점·시간 범위를 확인하고, 추출 후에는 값의 형식에 맞는 후속 기법만 선택한다.

### PCredz 분석

```bash
./Pcredz -h
PCREDZ_OUTPUT_DIR="$(mktemp -d "${PWD}/pcredz.XXXXXX")"
printf 'PCredz output: %s\n' "$PCREDZ_OUTPUT_DIR"
./Pcredz -f '<PCAP_FILE>' -o "$PCREDZ_OUTPUT_DIR" -t -v
find "$PCREDZ_OUTPUT_DIR" -xdev -type f -printf '%p %s bytes\n'
```

현재 upstream은 `-o <DIR>`로 `logs/`의 형식별 파일과 `CredentialDump-Session.log`를 지정한 출력 경로에 보존한다. 설치된 구버전에 `-o`가 없으면 임의 경로에서 실행하지 말고 빈 고유 디렉터리를 현재 위치로 삼아 실제 생성 파일을 기록한다.

확인할 출력:

- 평문 사용자명·비밀번호, NetNTLMv1/v2 challenge-response, Kerberos ticket·AS-REP/TGS hash, HTTP Basic 인증 등과 해당 송수신 호스트·서비스.
- 파일을 열지 못하면 pcap 경로·형식·읽기 권한을, 결과가 없으면 캡처 범위와 암호화 여부를 확인한다.

여러 pcap을 재귀 분석할 때는 같은 출력 디렉터리에 대해 다음을 사용하고 파일별 시간·endpoint 문맥을 보존한다.

```bash
./Pcredz -d '<PCAP_DIRECTORY>' -o "$PCREDZ_OUTPUT_DIR" -t
```

### 라이브 인터페이스 관찰

라이브 캡처는 대상 트래픽이 실제로 지나고 캡처 권한이 있는 호스트에서만 실행한다. 전용 terminal에서 PID를 즉시 기록하고 예정한 범위가 끝나면 계속 수집하지 않도록 종료한다.

```bash
sudo -s
PCREDZ_OUTPUT_DIR='<PCREDZ_OUTPUT_DIR>'
./Pcredz -i '<INTERFACE>' -o "$PCREDZ_OUTPUT_DIR" -t -v &
PCREDZ_PID=$!
ps -p "$PCREDZ_PID" -o pid=,user=,args=
```

`sudo -s`로 연 elevated Linux shell 안에서 후속 명령을 실행해 `$!`가 sudo wrapper가 아닌 PCredz 작업 PID를 가리키게 한다. `ps`가 기록한 PID·인터페이스·Pcredz 명령을 표시하지 않으면 프로세스 시작 실패·인터페이스 이름·캡처 권한·pcapy-ng 의존성을 먼저 확인한다.

### Wireshark 필터 후보

```text
http.authorization
ftp.request.command == "PASS"
smb2 || ntlmssp
smtp || pop || imap
snmp
kerberos
```

확인할 출력:

- HTTP 인증 헤더, FTP `PASS`, 메일 프로토콜의 인증 명령·응답, SNMP community가 포함된 packet, NTLM challenge/response와 Kerberos principal·message type.
- `smtp`, `pop`, `imap`, `snmp`, `kerberos`는 먼저 해당 프로토콜 packet의 존재와 송수신 주체를 좁히는 display filter다. packet이 보인다는 사실만으로 평문 비밀번호·재사용 가능한 ticket을 확보했다고 판단하지 않고 세부 field와 PCredz 추출 결과를 대조한다.

## 확인할 출력과 권한

- 평문 사용자명·비밀번호, NetNTLM challenge-response, Kerberos ticket·AS-REP/TGS hash를 서로 다른 형식으로 구분한다.
- pcap 읽기 권한과 라이브 패킷 캡처 권한은 다르며 라이브 캡처에는 별도 시스템 권한이 필요할 수 있다.
- 수집한 값의 유효성 및 서비스 권한은 실제 인증 단계에서 별도로 확인한다.
- NetNTLM challenge-response는 Windows 계정의 NT hash가 아니며, Kerberos 패킷이 보인다는 사실만으로 재사용 가능한 ticket을 확보한 것도 아니다.

## 변경 영향과 로컬 산출물 정리

오프라인 분석은 입력 pcap을 읽고 출력 디렉터리에 형식별 credential·hash·session log를 만든다. 라이브 분석은 추가로 PCredz 프로세스와 캡처 인터페이스 사용 상태를 만든다. 먼저 라이브 프로세스를 종료한 뒤 출력을 인계하거나 정리한다.

```bash
kill "$PCREDZ_PID"
wait "$PCREDZ_PID"
ps -p "$PCREDZ_PID"
```

`ps`가 해당 PID를 반환하지 않아야 라이브 관찰 종료가 확인된다. 이미 연결이 끊겼다면 해당 PID가 없음을 확인하고 출력은 완료된 캡처로 단정하지 않은 채 부분 결과로 표시한다. 이후 고유 출력 경로를 다시 확인하고, 이번 작업이 만든 파일·빈 디렉터리만 하위에서부터 정리한다.

```bash
find "$PCREDZ_OUTPUT_DIR" -xdev -depth -type f -delete
find "$PCREDZ_OUTPUT_DIR" -xdev -depth -type d -empty -delete
test ! -e "$PCREDZ_OUTPUT_DIR"
```

두 번째 `find`후 경로가 남으면 예상하지 않은 파일 형식·소유자·열린 프로세스를 먼저 확인하고 정리 완료로 표시하지 않는다. 라이브 분기에서 `sudo -s`로 연 shell은 정리 확인 후 `exit`로 닫는다. 입력 pcap·이미 전송된 credential·터미널 scrollback·원격 탐지 로그는 이 로컬 출력 삭제로 제거되지 않는다.
