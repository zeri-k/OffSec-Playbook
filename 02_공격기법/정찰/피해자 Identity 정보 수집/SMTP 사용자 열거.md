# SMTP 사용자 열거

## 한 줄 판단

SMTP 클라이언트를 실행할 수 있는 호스트에서 인증 없이 도달 가능한 대상 SMTP 서비스에 후보와 임의 사용자 기준값을 같은 방식으로 요청하여, 반복되는 응답 차이로 사용자명·메일 주소 후보와 계정 형식을 수집한다.

## 사용할 때

- 현재 보유 정보: 대상의 25/TCP, 465/TCP 또는 587/TCP에서 SMTP 배너나 `EHLO` 응답을 확인했고 메일 주소·이름 규칙·직원명 wordlist 중 하나가 있다.
- 명령 실행 위치와 도달성: `telnet`, `netcat`, `openssl` 또는 `smtp-user-enum`을 실행할 수 있는 호스트에서 대상 SMTP 포트에 도달할 수 있다.
- 현재 계정과 권한: 사전 SMTP 인증 계정은 없으며, 서버가 인증 전에 허용하는 `VRFY`, `EXPN` 또는 envelope 단계의 `RCPT TO` 응답만 비교한다.
- 지금 가능한 행동과 결과: 후보와 명백히 존재하지 않는 사용자 응답을 같은 모드에서 비교해 사용자 존재 가능성을 좁힌다. 응답 차이는 비밀번호, 로그인 권한, 메일함 접근 또는 계정 활성 상태를 확정하지 않는다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | SMTP 도구가 있는 호스트에서 대상 포트에 도달 가능 | `telnet <TARGET> 25`, `nc -nv <TARGET> 25`의 `220` 배너와 `EHLO` 응답 | 대상 주소, 포트와 네트워크 경로를 재확인 |
| 현재 계정 또는 인증 수단 | 인증 전 명령 응답을 비교하는 상태 | `EHLO` 뒤 인증 요구 여부와 각 명령의 응답 확인 | 인증이 필수이면 이 기법으로 사용자 존재를 확정하지 않음 |
| 전송 계층 | 대상 포트에 맞는 평문, STARTTLS 또는 TLS 세션 | `EHLO`, `STARTTLS`와 포트 465/587 확인 | TLS 협상 실패와 SMTP 명령 거부를 분리 |
| 사용자 후보 | 후보 목록과 명백히 존재하지 않는 기준 사용자 준비 | 이름 규칙, 이메일과 wordlist 확인 | 랜덤 기준값 없이 모든 응답을 valid로 해석하지 않음 |
| 대상의 응답 조건 | 같은 모드에서 후보별 응답을 반복 비교할 수 있음 | `VRFY`, `EXPN`, `RCPT TO`별 응답 코드와 메시지 기록 | 명령 비활성, catch-all과 동일 응답 정책을 먼저 판별 |

## 확인할 단서

| 단서 | 의미 | 다음 행동 |
|---|---|---|
| `VRFY <USER>`가 `250`, `252` 계열로 응답 | 사용자 존재 가능성이 있으나 코드만으로 확정할 수 없음 | 임의 사용자 기준값과 다른 모드로 교차 확인 |
| `EXPN <ALIAS>`가 여러 주소 반환 | 메일링 리스트 또는 alias 확장 가능 | 그룹/부서 계정 후보 수집 |
| `RCPT TO:<USER@DOMAIN>` 응답 차이 | 수신자 검증 가능 | `smtp-user-enum -M RCPT`로 자동화 |
| 모든 사용자가 같은 응답 | 명령 비활성, catch-all, 동일 응답 정책 | 가짜 사용자 기준값으로 오탐 확인 |

## 실행

1. 명령 실행 호스트에서 `EHLO`로 SMTP 기능, STARTTLS와 인증 방식을 확인한다.
2. 같은 연결 조건에서 명백히 존재하지 않는 사용자와 후보 사용자의 응답을 비교한다.
3. `VRFY`, `EXPN`, `RCPT` 모드를 나눠 반복되는 차이만 사용자 후보로 기록한다.
4. 확인한 사용자명 후보는 [[원격 비밀번호 공격]], [[IMAP POP3 메일함 수집]], 웹 로그인 검증 후보로 넘긴다.

### 명령과 확인할 출력

#### 수동 사용자 확인

```bash
telnet <TARGET> 25
EHLO test.local
VRFY <USER>
EXPN <USER>
MAIL FROM:<test@<DOMAIN>>
RCPT TO:<user@<DOMAIN>>
```

확인할 출력:

- `250`, `252`, `550`, `551` 같은 응답 코드 차이.
- 존재하지 않는 사용자와 후보 사용자의 메시지 차이.

#### RCPT 모드 자동 열거

```bash
smtp-user-enum -M RCPT -U users.txt -D <DOMAIN> -t <TARGET>
```

확인할 출력:

- `<user>@<domain> exists` 또는 mode별 valid user 결과.

#### STARTTLS가 필요한 경우

```bash
openssl s_client -starttls smtp -connect <TARGET>:587
EHLO test.local
VRFY <USER>
```

확인할 출력:

- TLS 협상 이후 SMTP 명령을 보냈을 때 응답 코드 차이가 유지되는지 확인한다.

| TLS 요구 | 평문 세션의 명령만 제한됨 | 사용자 상태 미확인 | `openssl s_client -starttls smtp`, 465/587 포트 확인 |
| TLS 협상 또는 인증서 검증 전에 연결 실패 | SMTP 사용자 정책보다 전송 계층 또는 네트워크 문제 | 서비스 접근 미확정 | 대상 포트, STARTTLS·TLS 방식과 이름 해석 확인 |
| 연결 제한 | rate limit 또는 SMTP 정책 | 사용자 상태 미확인 | 속도 감소, 모드 변경, 수동 대화로 기준값 확인 |
| `john`, `john@domain.local` | 계정명과 메일 주소 형식 후보 확보 | 계정 후보 | [[원격 비밀번호 공격]] |
| `support-team`, `all`, `dev` | 메일링 리스트 확보 | 메일링 리스트 | 부서/역할 기반 계정 후보 확장 |
| SMTP 배너, 인증서 CN/SAN | 도메인/호스트 단서 확보 | 도메인/호스트 단서 | [[DNS 열거와 Zone Transfer]], 웹 vhost 확인 |

## 확인할 출력과 권한

- 가짜 사용자 기준값과 `250`·`252`·`550` 응답 차이를 같은 세션 조건과 모드에서 재현한다. 단일 응답 코드만으로 계정 존재를 확정하지 않는다.
- 인증 전 SMTP 응답은 사용자명·메일 주소 후보만 제공한다. 비밀번호, SMTP 인증 성공, 메일함 접근, 다른 서비스 로그인 권한과 계정 활성 상태는 별도 검증이 필요하다.
- `RCPT TO` 수락은 envelope 단계의 수신자 처리 결과이며 실제 메일 전달이나 [[25_SMTP#Open Relay 검증|SMTP Open Relay 검증]] 성공을 뜻하지 않는다.
- rate limit, 동일 응답 정책과 TLS 실패를 invalid 사용자 응답으로 분류하지 않는다.
