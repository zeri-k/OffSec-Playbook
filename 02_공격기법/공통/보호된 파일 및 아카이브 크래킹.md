# 보호된 파일 및 아카이브 크래킹

## 한 줄 판단

분석 호스트에서 읽을 수 있는 SSH private key, Office·PDF, ZIP·7z 또는 BitLocker 파일이 있으면 형식별 hash를 추출해 파일 비밀번호·passphrase를 복구하고, 원본을 열어 내부 credential과 key가 실제로 있는지 확인한다.

## 사용할 때

- 현재 보유 정보: SMB·NFS·FTP 또는 로컬 파일 시스템에서 암호화된 문서·archive·SSH private key·VHD를 회수했고 파일 출처와 예상 사용자를 알고 있다.
- 명령 실행 위치와 도달성: 보호 파일이 저장된 분석 호스트에서 2john·John·Hashcat을 실행할 수 있으며 오프라인 hash 추출·크래킹에는 원격 대상 접근이 필요하지 않다.
- 현재 가능한 행동과 결과: 보호 파일 자체의 비밀번호나 개인키 passphrase를 복구한 뒤 원본을 열거나 마운트해 내부 사용자명·평문 비밀번호·NT hash·API token·개인키·문서를 확인하며, 파일 비밀번호를 사용자 계정 비밀번호로 간주하지 않는다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | 분석 호스트에 보호 파일이 있고 로컬 도구 실행 가능 | 파일 경로·크기·읽기 가능 여부 확인 | 파일 회수·권한·손상 여부를 해결한 뒤 진행 |
| 현재 계정 또는 인증 수단 | 오프라인 hash 추출에는 원격 계정 불필요, 복구 후 원격 사용 시 파일 출처의 사용자·서비스 식별 필요 | 파일 소유자·원본 경로·주변 문맥 확인 | 복구한 비밀번호나 key의 적용 대상을 추정만 하지 말고 확인 |
| 현재 권한 | 보호 파일을 읽고 출력 hash를 저장하며 복구 후 원본을 열거나 마운트할 권한 보유 | 파일 ACL과 출력 경로 쓰기 확인 | 읽기·쓰기·마운트 권한을 단계별로 분리해 확인 |
| 공격 대상의 조건 | 실제 파일 형식이 식별되고 해당 형식의 hash 추출 도구가 지원 | `file`, 확장자와 2john 출력 확인 | 확장자만 믿지 말고 손상·다른 형식·지원 도구 확인 |
| 필요한 파일·목록·주소 | 원본 사본, 형식별 hash 파일과 wordlist·rule·mask 준비 | hash 파일이 비어 있지 않고 John/Hashcat이 인식 | 추출 명령·hash 형식·후보 목록을 다시 확인 |

## 실행

1. 분석 호스트에서 원본 파일 형식·무결성·읽기 권한과 예상 사용자·용도를 확인한다.
2. 원본을 변경하지 않고 형식별 2john 도구로 오프라인 크래킹용 hash를 만든다.
3. John 또는 Hashcat 결과에서 파일 비밀번호·passphrase를 확인한다.
4. 복구한 값으로 원본 파일을 열거나 마운트하고, 내부에서 나온 평문 비밀번호·NT hash·API token·개인키는 연결된 계정과 대상 서비스를 확인한 뒤 별도로 검증한다.

### SSH key

```bash
ssh2john.py id_rsa > ssh.hash
john --wordlist=rockyou.txt ssh.hash
john ssh.hash --show
```

확인할 출력:

- SSH private key의 passphrase. 이 값은 SSH 사용자 계정의 평문 비밀번호와 다른 결과다.

### Office/PDF/ZIP

```bash
office2john.py Protected.docx > office.hash
pdf2john.py file.pdf > pdf.hash
zip2john archive.zip > zip.hash
john --wordlist=rockyou.txt office.hash
```

확인할 출력:

- 해당 Office·PDF·ZIP 파일을 여는 비밀번호. 파일 내부 credential 존재 여부는 원본을 연 뒤 확인한다.

### BitLocker

```bash
bitlocker2john -i Backup.vhd > backup.hashes
grep "bitlocker\\$0" backup.hashes > backup.hash
hashcat -m 22100 backup.hash rockyou.txt --backend-ignore-opencl -d 1 -O -w 3
```

확인할 출력:

- BitLocker password, 이후 dislocker 마운트 가능.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 2john 도구에서 hash 출력 | 파일 형식 분석과 hash 추출 성공 | 오프라인 크래킹 대상 확보 | John 또는 Hashcat으로 복구 시도 |
| John/Hashcat에서 비밀번호 또는 passphrase 출력 | 보호 파일 잠금 해제 값 복구 | 해당 파일 복호화 가능 | 원본 파일을 열어 내용과 실제 접근 범위 확인 |
| credential, key, 내부 문서 또는 URL | 보호 파일 내부 정보 노출 | 자격증명 또는 내부 정보 확보 | 관련 서비스에서 유효성과 권한 검증 |
| SSH key 또는 VHD 사용 성공 | 복구한 비밀번호·개인키 또는 볼륨 암호의 실제 사용 확인 | SSH 접근 또는 파일 시스템 접근 확보 | 세션 Identity와 파일 권한 확인 |
| hash 추출 실패 | 파일 형식 불일치 또는 손상 | 크래킹 대상 미생성 | `file`과 해당 형식의 2john 도구 확인 |
| crack 실패 | 강한 비밀번호 또는 후보 부족 | hash만 확보 | CeWL, 규칙, 파일명 기반 후보 검토 |
| mount 실패 | 복호화, 파티션 또는 경로 문제 | 비밀번호 복구 후 접근 미완료 | dislocker 경로, loop device, recovery key 확인 |

## 확인할 출력과 권한

- hash 추출, 비밀번호 복구, 파일 열기 또는 마운트 성공을 각각 확인한다.
- 보호 파일 접근 권한은 내부 credential이 가리키는 계정 권한과 동일하지 않다.
- SSH key나 VHD를 사용할 때 실제 사용자와 접근 가능한 파일 범위를 별도로 확인한다.
- 보호 파일 비밀번호·SSH key passphrase, 파일 내부의 평문 계정 비밀번호와 private key 자체를 서로 다른 값으로 기록한다.
