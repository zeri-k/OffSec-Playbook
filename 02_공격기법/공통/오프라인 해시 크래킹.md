# 오프라인 해시 크래킹

## 한 줄 판단

분석 호스트에 계정·출처가 식별된 hash가 있으면 NTLM·DCC2·NetNTLMv2 등 정확한 format과 mode를 선택해 일치하는 평문 비밀번호 후보를 복구하고, 원본 계정 형식과 대상 서비스에서 현재 유효한지 별도로 검증한다.

SAM·NTDS·LSASS·IPMI·NetNTLM·Linux shadow·DB에서 얻은 hash의 사용자·도메인·호스트·수집 출처를 알고, hash 파일이 있는 분석 호스트에서 John·Hashcat을 실행할 수 있을 때 사용한다. DCC2·NetNTLMv2·문서 hash를 NT hash로 오인하지 않으며 평문 후보의 서비스 유효성은 별도 검증한다.

## 실행

### hash 유형 식별

이 block은 분석 호스트에서 실행한다. `hashes.txt`는 사용자·도메인·호스트 출처를 잃지 않은 입력 파일이며, 지원 형식 검색은 mode를 확정하지 않는다.

```bash
hashid hashes.txt
john --list=formats | rg -i nt
hashcat --example-hashes --backend-ignore-opencl -d 1 -O -w 3 | rg -i ntlm
```

확인할 출력:

- NTLM, NetNTLMv2, DCC2, SHA512crypt, IPMI 등 정확한 형식 후보와 대응 mode.
- `Token length exception`, `Separator unmatched` 또는 `No hashes loaded`가 나오면 비밀번호 후보 문제가 아니라 hash 라인·구분자·mode를 먼저 확인한다.

### Hashcat

`ntlm.hashes`·`dcc2.hashes`·`netntlmv2.hashes`는 서로 다른 credential hash 형식의 입력 파일이고 `rockyou.txt`는 분석 호스트 wordlist 경로다. 형식이 확인된 입력 파일 하나만 선택한다.

```bash
hashcat -m 1000 ntlm.hashes rockyou.txt --backend-ignore-opencl -d 1 -O -w 3
hashcat -m 2100 dcc2.hashes rockyou.txt --backend-ignore-opencl -d 1 -O -w 3
hashcat -m 5600 netntlmv2.hashes rockyou.txt --backend-ignore-opencl -d 1 -O -w 3
```

확인할 출력:

- `hash:password`, recovered count.

### John

`hashes.txt`와 `rockyou.txt`는 앞 단계 분석 호스트 입력을 재사용한다. `--show`는 potfile 후보를 표시할 뿐 원격 인증 성공을 뜻하지 않는다.

```bash
john --wordlist=rockyou.txt hashes.txt
john hashes.txt --show
```

확인할 출력:

- cracked password와 남은 hash 수.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 도구가 hash를 올바른 형식으로 인식 | hash type과 mode 식별 성공 | 크래킹 준비 완료 | wordlist, rule 또는 mask 선택 |
| `hash:password` 또는 John의 cracked 결과 | 평문 비밀번호 복구 | credential 후보 확보 | 잠금 정책 확인 후 대상 서비스에서 검증 |
| 정상 클라이언트로 SSH, SMB, WinRM, RDP 또는 DB 인증 성공 | 복구한 평문이 해당 계정 형식과 서비스에서 현재 유효함 | 해당 서비스 인증 성공 | [[확보한 자격 증명으로 원격 접근 경로 선택]]에서 세션과 실제 권한 확인 |
| mode 오류 또는 token length 오류 | hash 형식 오판 또는 입력 손상 | 크래킹 미시작 | 수집 출처와 전체 hash 형식 재확인 |
| crack 실패 | 강한 비밀번호 또는 wordlist 부적합 | hash만 확보 | rule, mask, CeWL, 정책 기반 후보 검토 |
| 속도가 지나치게 낮음 | 느린 hash 또는 자원 제약 | 크래킹 진행성 낮음 | 우선순위와 PtH/relay 가능성 재평가 |

## 확인할 출력과 권한

- recovered count와 실제 `hash:password` 출력을 확인하고 이미 cracked 된 결과는 `--show`로 재확인한다.
- 평문 복구는 credential 후보 확보이며 계정 활성 상태나 서비스 권한을 보장하지 않는다.
- 로컬 계정과 도메인 계정, 일반 사용자와 관리자 권한을 인증 후 분리한다.
- NTLM hash는 조건이 맞으면 [[Pass the Hash]] 후보가 될 수 있지만 DCC2와 NetNTLMv2는 NT hash가 아니며 그대로 PtH에 사용하지 않는다.
