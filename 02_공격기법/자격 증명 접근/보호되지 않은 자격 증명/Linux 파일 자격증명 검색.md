# Linux 파일 자격증명 검색

## 한 줄 판단

Linux 파일시스템에서 설정·스크립트·로그를 읽을 수 있으면 비밀번호·token·접속 문자열과 적용 계정·서비스 단서를 함께 수집한다.

## 사용할 때

- 현재 보유 정보: 현재 Linux 사용자와 읽을 수 있는 홈·웹 루트·설정·로그 경로를 알고 있다.
- 명령 실행 위치: 대상 Linux shell 또는 대상 파일시스템이 마운트된 분석 호스트다.
- 현재 가능한 행동과 결과: 파일에 저장된 값을 수집할 수 있지만 값의 최신성, 계정 소유자와 실제 서비스 인증은 별도 검증한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 읽기 범위 | 현재 shell에서 홈·웹·설정·로그 경로를 읽을 수 있음 | `find`, `ls -la`와 권한 오류 확인 | 현재 계정이 읽을 수 있는 경로로 검색 축소 |
| 검색 대상과 키워드 | 애플리케이션 설정·스크립트·로그 경로 또는 문자열 후보 | 파일 확장자, 최근 수정 시각과 서비스 종류 확인 | 애플리케이션 경로와 키워드 조정 |
| 검증 대상 서비스 | 발견 값이 적용되는 SSH·DB·웹·`su`·`sudo` 대상이 식별됨 | URL, connection string, 계정명과 파일 문맥 확인 | 환경명·호스트명·계정명을 먼저 해석 |

## 실행

### 설정과 스크립트 검색

```bash
for ext in conf config cnf env ini yml yaml php py sh; do find / -name "*.$ext" 2>/dev/null; done
rg -i "password|passwd|pwd|secret|token|user|key" /var/www /home /opt 2>/dev/null
```

확인할 출력:

- DB 계정, API token, 내부 URL과 자격 증명 값이 기록된 파일 경로.
- 예시값·폐기된 환경 변수를 구분할 계정명, 대상 서비스와 파일 수정 시각.

### 로그의 자격 증명 단서 검색

```bash
rg -i "password|accepted|sudo|COMMAND=|ssh" /var/log 2>/dev/null
```

확인할 출력:

- 인증 성공 계정, 명령 인자에 남은 값과 대상 서비스 단서.
- 로그의 `Accepted` 기록은 과거 인증 사실이며 현재 비밀번호를 확보했다는 뜻이 아니다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 설정·스크립트에 비밀번호, DB credential 또는 API token이 있음 | 파일 기반 자격 증명 노출 | 서비스 credential 후보 확보 | 계정 형식과 대상 서비스를 확인해 정상 클라이언트로 검증 |
| 내부 URL·호스트명과 계정명이 함께 있음 | 값의 적용 대상 식별 가능 | 검증 대상 서비스 후보 | 현재 네트워크 경로와 서비스 인증 방식 확인 |
| 검색 결과가 과다함 | 범위와 키워드가 넓음 | 유효 단서 미선별 | `/var/www`, `/opt`, `/home`과 최근 수정 파일 우선 |
| 읽기 거부 | 현재 사용자 권한 부족 | 접근 가능한 파일 범위만 확인 | 다른 읽기 가능한 경로 또는 권한 상승 후보 검토 |

## 확인할 출력과 권한

- 파일 경로, 실제 값, 계정명과 적용 서비스를 함께 확인해야 자격 증명 후보로 판정한다.
- 파일 읽기 권한은 파일에 적힌 계정의 권한과 동일하지 않다.
- 인증 성공 뒤 대상 서비스 권한과 로컬·도메인 계정 범위를 따로 확인한다.
