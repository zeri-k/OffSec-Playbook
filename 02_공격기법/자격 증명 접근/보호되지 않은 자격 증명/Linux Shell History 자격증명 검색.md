# Linux Shell History 자격증명 검색

## 한 줄 판단

Linux 사용자의 shell history를 읽을 수 있으면 명령 인자에 남은 비밀번호·token과 `su`·`sudo`·`ssh`·DB 대상 단서를 수집한다.

## 사용할 때

- 현재 보유 정보: 현재 Linux 사용자와 읽을 수 있는 사용자 홈 경로를 알고 있다.
- 명령 실행 위치: 대상 Linux shell 또는 사용자 홈이 마운트된 분석 호스트다.
- 현재 가능한 행동과 결과: 과거 명령을 읽어 자격 증명 후보를 얻을 수 있지만 값의 현재 유효성과 명령 실행 성공 여부는 별도 확인한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 읽기 범위 | 대상 사용자의 history 파일을 읽을 수 있음 | 홈 디렉터리와 파일 권한 확인 | 현재 사용자가 읽을 수 있는 홈만 확인 |
| 공격 대상의 조건 | history 기록이 남아 있고 명령의 대상 계정·서비스를 해석할 수 있음 | 파일 크기·수정 시각과 명령 문맥 확인 | 다른 사용자 홈과 애플리케이션 history 파일 확인 |

## 실행

```bash
tail -n 50 /home/*/.bash_history 2>/dev/null
```

확인할 출력:

- 명령 인자에 직접 포함된 비밀번호·token·connection string.
- `su`, `sudo`, `ssh` 또는 DB 클라이언트 명령에 표시된 사용자명·호스트명과 대상 서비스.
- 명령이 기록됐다는 사실만으로 성공적으로 실행됐거나 값이 현재 유효하다고 판정하지 않는다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 명령 인자에 평문 비밀번호 또는 token이 있음 | shell history에 자격 증명 노출 | 계정·서비스가 연결된 credential 후보 | [[확보한 자격 증명으로 원격 접근 경로 선택]] |
| 사용자명·호스트만 있고 비밀번호가 없음 | 접근 대상 단서만 확인 | 계정 또는 서비스 후보 | [[Linux 파일 자격증명 검색]]에서 관련 설정 확인 |
| history가 비어 있거나 읽기 거부 | 기록 없음 또는 현재 권한 부족 | 자격 증명 미확인 | 다른 읽기 가능한 홈과 파일 기반 검색 확인 |

## 확인할 출력과 권한

- 값과 같은 명령에 표시된 사용자·호스트·서비스를 함께 기록한다.
- history의 값은 과거 입력일 수 있으므로 현재 인증 성공과 권한을 따로 확인한다.
