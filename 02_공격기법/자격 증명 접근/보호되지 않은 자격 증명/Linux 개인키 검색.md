# Linux 개인키 검색

## 한 줄 판단

Linux 파일시스템의 홈·설정 경로를 읽을 수 있으면 개인키 파일과 연결된 사용자·호스트 단서를 찾아 암호화 여부에 따라 인증 검증 또는 오프라인 크래킹으로 분기한다.

## 사용할 때

- 현재 보유 정보: 현재 Linux 사용자와 읽을 수 있는 홈·애플리케이션 경로를 알고 있다.
- 명령 실행 위치: 대상 Linux shell 또는 대상 파일시스템이 마운트된 분석 호스트다.
- 현재 가능한 행동과 결과: 개인키 파일을 찾고 읽을 수 있지만 해당 키가 어느 계정·호스트에서 유효한지는 별도 확인한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 읽기 범위 | 홈·설정 경로에서 파일 검색과 읽기 가능 | `find`, `ls -l`과 권한 오류 확인 | 읽을 수 있는 사용자 홈으로 범위 축소 |
| 공격 대상의 조건 | 키와 연결할 사용자명·호스트명 또는 SSH config 단서가 있음 | 파일 소유자, 경로, 주석과 설정 확인 | `~/.ssh/config`, 스크립트와 배포 설정 확인 |
| 필요한 파일·목록·주소 | 키 사본과 원본 권한·암호화 상태를 기록할 위치 | 파일 헤더와 권한 확인 | 원본 파일을 수정하지 않고 읽기 가능한 사본 준비 |

## 실행

```bash
find / -name "id_rsa" -o -name "id_ed25519" -o -name "*.pem" 2>/dev/null
grep -rnE '^\-{5}BEGIN [A-Z0-9 ]+PRIVATE KEY\-{5}$' /home /root 2>/dev/null
```

확인할 출력:

- 개인키 경로, 파일 소유자와 private key header.
- 암호화된 키인지 여부와 연결된 사용자·호스트 단서.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 읽을 수 있는 개인키와 사용자·호스트 단서가 있음 | 키 기반 인증 후보 확보 | SSH 인증 검증 가능 | [[SSH credential 및 키 인증 검증]] |
| 암호화된 개인키 | 키는 확보했으나 passphrase 필요 | 오프라인 크래킹 대상 확보 | [[보호된 파일 및 아카이브 크래킹]] |
| 키 파일명만 있고 읽기 거부 | 현재 계정에 파일 읽기 권한이 없음 | 키 미확보 | 파일 ACL과 현재 계정 확인 |
| 인증 실패 | 키·사용자·호스트 조합이 맞지 않거나 키가 폐기됨 | 원격 접근 미확인 | 키 주석, SSH config와 대상 계정 재확인 |

## 확인할 출력과 권한

- 파일명 발견, 개인키 내용 읽기, 암호화 해제와 실제 SSH 인증을 서로 다른 성공 단계로 본다.
- 개인키 읽기 권한은 대상 원격 계정의 로그인 권한이나 관리자 권한을 보장하지 않는다.
