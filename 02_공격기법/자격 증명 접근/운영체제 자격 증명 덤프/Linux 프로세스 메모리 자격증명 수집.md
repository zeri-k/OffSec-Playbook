# Linux 프로세스 메모리 자격증명 수집

## 한 줄 판단

Linux 호스트에서 root 또는 대상 프로세스 메모리 읽기 권한을 확보했으면, 현재 로그온 세션과 관련 프로세스 메모리에서 사용자명·평문 비밀번호 후보를 추출하고 실제 서비스 인증 전 후보로 분리한다.

## 사용할 때

- Linux에서 root 권한을 확보했고 활성 사용자 세션이 있을 때.
- 설정 파일·history·개인키 검색과 별도로 메모리에 남은 평문 후보를 확인할 때.
- `mimipenguin`이 현재 배포판과 로그인 환경을 지원할 때.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 현재 권한 | root 또는 대상 프로세스 메모리 읽기 가능 | `id`, 실행 오류 | [[Linux 권한 상승 열거]]에서 다른 경로 확인 |
| 활성 세션 | 로그인·인증 관련 프로세스 존재 | `ps`, `who` | 파일·history·개인키 검색으로 전환 |
| 도구 호환성 | Python 또는 Bash 구현 실행 가능 | 버전·의존성 오류 확인 | 다른 구현 또는 수동 메모리 분석 검토 |

## 실행

### Python 구현

```bash
sudo python3 mimipenguin.py
```

### Bash 구현

```bash
sudo bash mimipenguin.sh
```

확인할 출력:

- `[SYSTEM - GNOME] <USER>:<PASSWORD>` 또는 사용자명·평문 비밀번호 형태의 후보.
- `permission denied`나 모듈 오류는 자격 증명 부재가 아니라 현재 권한·환경 미지원일 수 있다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 사용자명과 평문 비밀번호 후보 출력 | 메모리·세션 흔적에서 자격 증명 후보 추출 | 평문 자격 증명 후보 | [[확보한 자격 증명으로 원격 접근 경로 선택]]에서 대상 계정·서비스 확인 |

| permission denied | 프로세스 메모리 읽기 권한 부족 | 시작 상태 유지 | 실제 UID·capability·보호 설정 확인 |

## 확인할 출력과 권한

- 출력된 문자열이 어느 사용자와 세션에서 나왔는지 확인한다.
- 평문처럼 보이는 값도 대상 서비스에서 검증하기 전에는 현재 사용 가능한 자격 증명으로 확정하지 않는다.
