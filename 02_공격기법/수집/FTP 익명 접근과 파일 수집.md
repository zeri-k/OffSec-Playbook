# FTP 익명 접근과 파일 수집

## 한 줄 판단

현재 명령 실행 위치에서 대상 FTP 제어·데이터 채널에 연결할 수 있으면 익명 또는 보유 계정으로 로그인해 실제로 읽을 수 있는 원격 경로를 확인하고 설정·백업·키·비밀번호 후보 파일을 수집하며, 필요하면 고유 검증 파일로 디렉터리 쓰기 권한을 확인한다.

## 사용할 때

- 21/TCP의 FTP 서비스에서 anonymous 로그인이 허용될 가능성이 있을 때.
- FTP 계정으로 로그인했고 설정·백업·소스·키 파일을 찾을 때.
- 로그인 성공, 목록 조회와 실제 파일 읽기를 구분해야 할 때.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 네트워크 경로 | 제어·데이터 채널 접근 | 배너와 로그인 뒤 `ls`·`get` 결과 | Active·Passive 모드와 방화벽 확인 |
| 인증 컨텍스트 | anonymous 또는 특정 FTP 계정 | `230` 응답과 실제 시작 디렉터리 | anonymous 거부와 계정 인증 실패를 구분 |
| 수집 대상 | 설정·백업·소스·키 파일 후보 | 파일명·크기·수정 시각 확인 | 필요한 파일만 선택 |

## 실행

### 익명 로그인

```bash
ftp <TARGET>
Name: anonymous
Password: anonymous@
```

### 명명 계정 로그인

```bash
ftp <TARGET>
Name: <USER>
Password: <PASSWORD>
```

로그인 뒤 파일 목록과 전송 결과를 확인한다.

```text
ftp> ls -la
ftp> binary
ftp> get <FILE>
ftp> mget <MATCHED_FILES>
```

확인할 출력:

- `230` 계열 로그인 성공 응답과 어느 계정을 사용했는지.
- directory listing과 `get` 완료 응답.
- 로컬 파일 크기·hash와 설정·백업·키·비밀번호 후보 내용.

### 쓰기 권한 확인

업로드 뒤 직접 조회하고 지울 수 있는 경로에서 고유 검증 파일 하나로 쓰기 권한을 확인한다.

```bash
printf 'FTP write verification\n' > <UNIQUE_PROOF>
ftp <TARGET>
ftp> put <UNIQUE_PROOF>
ftp> ls -la <UNIQUE_PROOF>
ftp> delete <UNIQUE_PROOF>
ftp> ls -la <UNIQUE_PROOF>
```

확인할 출력:

- `put` 완료와 원격 목록의 정확한 파일명·크기.
- 삭제 뒤 같은 파일이 더 이상 반환되지 않는지.
- 업로드 성공은 해당 디렉터리의 파일 생성 권한만 보여 주며 실행 권한을 뜻하지 않는다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| anonymous 로그인과 목록 조회 성공 | 익명 계정에 목록 권한 | 익명 FTP 접근 | 파일별 READ 확인 |
| `get` 완료 후 파일 크기·hash가 안정적 | 해당 파일을 온전히 읽음 | 설정·백업·키 파일 수집 | 자격 증명·키 형식과 대상 서비스 확인 |
| 로그인은 되지만 전송 실패 | 데이터 채널 또는 파일 권한 문제 | FTP 제어 채널만 확인 | Passive 모드·데이터 포트·파일별 권한 확인 |
| 검증 파일 업로드와 삭제 성공 | 현재 계정으로 해당 디렉터리에 파일 생성·삭제 가능 | FTP 쓰기 권한 | 업로드할 실제 파일과 서버 측 사용 경로를 별도로 판단 |

## 확인할 출력과 권한

- `230`, 디렉터리 목록과 파일 다운로드 성공을 서로 다른 상태로 기록한다.
- 파일에서 찾은 사용자명·비밀번호·key는 실제 서비스 인증 전까지 후보로 유지한다.

## 변경 영향과 복구

- 쓰기 확인은 기존 파일을 덮어쓰지 않는 고유 이름만 사용한다.
- 확인 직후 `delete <UNIQUE_PROOF>`를 실행하고 원격 목록에서 제거됐는지 확인한다.
