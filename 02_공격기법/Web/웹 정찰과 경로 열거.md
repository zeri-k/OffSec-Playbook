# 웹 정찰과 경로 열거

## 한 줄 판단

현재 명령 실행 위치에서 대상 HTTP·HTTPS 포트에 연결할 수 있다면, 응답 가상 호스트·기술 지문·숨은 경로·JavaScript·API·과거 URL을 확인해 인증, 파일 업로드·다운로드와 공개 exploit 중 실제로 시도할 수 있는 분기를 고른다.

## 시작 조건 해석


- 80/443 또는 8080/8443 계열에서 웹 응답, redirect, title, 인증서 단서가 확인될 때.
- 서비스 지문은 보이지만 바로 검증할 취약점이나 기능이 아직 정리되지 않았을 때.
- 웹에서 계정, 업로드, API, 관리 콘솔, 제품형 exploit 후보를 골라야 할 때.

## 전제 조건

| 조건 | 확인 방법 | 충족 기준 |
|---|---|---|
| 웹 응답 | `curl`, 브라우저 | HTTP status/title/redirect 확인 |
| Host 후보 | IP, DNS, 인증서 SAN, redirect | Host 헤더 또는 vhost 후보 |
| 열거 기준 | 기준 404/403 응답 | wildcard/custom 404 구분 가능 |

## 실행

1. [[웹 지문 확인과 공격면 분류]]로 제품, 프레임워크, TLS, WAF, vhost 단서를 잡는다.
2. [[웹 숨은 경로와 민감 파일 열거]]로 디렉터리, 파일, vhost, 백업을 확인한다.
3. [[웹 단서 기반 기능 열거]]로 robots, `.well-known`, JS, API, archive, 검색 단서를 보강한다.
4. 나온 기능을 [[웹 파일 업로드와 Web Shell]], [[WebDAV PUT 업로드와 실행]], [[Public Exploit 검토와 검증]]으로 분기한다.

공격 호스트에서 최소 정찰 명령을 실행해 응답과 경로 열거 기준선을 만든다.

```bash
curl -k -i https://<TARGET>/
whatweb https://<TARGET>/
gobuster dir -u https://<TARGET>/ -w <WORDLIST> -k
```

확인할 출력:

- HTTP status, redirect, `Server` 헤더, title과 기술 지문.
- 기준 404·403과 다른 status·길이를 반환하는 경로.
- Host 또는 vhost가 필요하면 확인된 이름을 URL과 Host header에 적용해 다시 실행한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 관리 경로, API, 업로드, 백업, 설정 파일 또는 제품형 콘솔이 확인된다. | 웹 기능별 공격면 분류 | 웹 기능 후보 | 업로드는 [[웹 파일 업로드와 Web Shell]], 제품은 [[Public Exploit 검토와 검증]]으로 분기 |
| Host header 또는 vhost에 따라 다른 애플리케이션이 열린다. | 별도 가상 호스트 확인 | 추가 웹 애플리케이션 | [[웹 지문 확인과 공격면 분류]]와 [[웹 숨은 경로와 민감 파일 열거]]를 새 호스트에 적용 |
| 다운로드 가능한 파일에서 credential이나 내부 정보가 나온다. | 파일 기반 인증·내부 서비스 단서 확인 | 자격 증명·서비스 단서 | 계정 형식과 내부 서비스 주소를 확인해 해당 서비스 기법으로 전달 |
| 기본 페이지뿐 | vhost/Host header 필요 | 시작 상태 유지 | DNS, 인증서 SAN, gobuster vhost |
| 경로 열거 결과 없음 | wordlist/스택 불일치 | 시작 상태 유지 | JS/robots/archive 단서 기반 재시도 |
| 인증 필요 | 정상 제한 | 시작 상태 유지 | 계정 후보, 기본 credential, 권한 차이 확인 |

## 확인할 출력과 권한

- 판정 기준: 하위 기법에서 확인된 제품, 경로, 파일, 기능만 결과 상태로 올리고 단순 후보는 미확정으로 둔다.
- 권한 구분: 인증 전·익명·유효 계정 상태를 구분하고, 서비스 응답만으로 실제 권한을 추정하지 않는다.
