# 웹 숨은 경로와 민감 파일 열거

## 한 줄 판단

대상 웹 가상 호스트와 존재하지 않는 경로의 기준 응답을 알고 있다면, 디렉터리·파일·추가 가상 호스트 응답을 기준과 비교해 실제 존재하는 경로와 민감 파일을 찾고 그 기능에 맞는 공격기법으로 연결한다.

## 시작 조건 해석


- 기본 페이지에서 기능이 적거나 링크가 제한적일 때.
- 401/403/301/302/200 응답 차이로 숨은 경로가 의심될 때.
- vhost 기반으로 실제 애플리케이션이 분기될 가능성이 있을 때.

## 전제 조건

| 조건 | 확인 방법 | 충족 기준 |
|---|---|---|
| 기준 응답 | 존재하지 않는 경로 요청 | baseline status·length·title 확인 |
| wordlist | 기술 스택/언어별 선택 | 경로 후보 확보 |
| Host 후보 | DNS/인증서/메일/배너 | vhost brute force 가능 |
| 접근 상태 | 익명·인증 사용자 구분 | 인증·인가 경계를 비교 가능 |

## 실행

1. 없는 경로로 baseline status, length와 title을 확인한다.
2. 디렉터리와 파일 확장자를 나눠 열거한다.
3. vhost 후보가 있으면 Host header 기반으로 별도 열거한다.
4. 찾은 경로를 인증, 인가, 입력 처리, SSRF, 파일 읽기, 업로드, 제품형 기능으로 분류한다.

### 명령과 확인할 출력

#### 방식 선택

| 현재 확인할 대상 | 사용할 방식 | 성공 시 얻는 결과 | 실패 시 다음 확인 |
|---|---|---|---|
| 존재하지 않는 경로의 공통 응답 | `curl -i` 기준 요청 | status·length·redirect·title 기준값 | CDN·WAF·세션에 따라 응답이 변하는지 반복 확인 |
| 숨은 디렉터리 후보 | `gobuster dir` 기본 wordlist | 기준 응답과 다른 디렉터리 후보 | wildcard와 제외 길이, wordlist 적합성 확인 |
| 백업·설정·소스 파일 확장자 후보 | `gobuster dir -x` | 실제 응답이 다른 파일 후보 | 기술 스택에 맞는 확장자와 기준 응답 재조정 |
| DNS·인증서·리다이렉션에서 얻은 vhost 후보 | `gobuster vhost`와 Host header 검증 | IP는 같지만 다른 Host에서 제공되는 웹 애플리케이션 후보 | DNS 해석과 기준 Host 응답을 비교 |
| 발견한 경로 또는 파일 후보 | `curl -i`, `curl -o` | 실제 응답 본문 또는 내려받은 파일 | 오류 페이지·빈 파일·리다이렉션 저장 여부 확인 |

#### 1. 존재하지 않는 경로의 기준 응답 확인

```bash
curl -i http://<TARGET>/<NONEXISTENT_PATH>
```

확인할 출력:

- 존재하지 않는 요청의 status, `Content-Length`, redirect 위치와 응답 제목을 기록한다.
- 요청마다 길이·토큰이 달라지면 고정 길이만으로 후보를 판정하지 말고 body의 공통 패턴도 비교한다.

#### 2. 디렉터리 후보 열거

```bash
gobuster dir -u http://<TARGET>/ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt
```

확인할 출력:

- 기준 응답과 다른 `200`, `301`, `302`, `401`, `403`, length와 redirect.
- 모든 후보가 같은 응답이면 wildcard·custom 404를 먼저 조정한다.

#### 3. 파일 확장자 후보 열거

```bash
gobuster dir -u http://<TARGET>/ -w words.txt -x php,txt,bak,old,zip,conf
```

확인할 출력:

- backup, source, config, environment, log와 기술 스택에 맞는 파일 후보.
- 후보가 반환됐다는 사실만으로 파일 내용을 읽었다고 판정하지 않고 `curl`로 직접 검증한다.

#### 4. 가상 호스트 열거와 직접 검증

```bash
gobuster vhost -u http://<DOMAIN>/ -w subdomains.txt --append-domain
curl -H 'Host: <VHOST>' http://<TARGET>/
```

확인할 출력:

- 기본 Host와 다른 status, length, title 또는 애플리케이션 내용.
- 이름 후보만 나오거나 모든 Host가 같은 응답이면 wildcard DNS·기본 vhost와의 차이를 재확인한다.

#### 5. 발견한 경로와 파일 확인

```bash
curl -i http://<TARGET>/<PATH>
test ! -e '<LOCAL_FILE>'
curl -f -o '<LOCAL_FILE>' http://<TARGET>/<REMOTE_FILE>
```

`test`가 실패하면 기존 파일을 덮어쓰지 않고 새 `<LOCAL_FILE>`을 정한다. `curl -f`는 HTTP 400 이상에서 실패하지만 redirect body·인증 페이지·wildcard 응답은 저장할 수 있으므로 status·Content-Type·크기·hash와 본문을 계속 대조한다.

확인할 출력:

- 응답 body에서 API 문서, 로그인, 업로드·다운로드 기능 또는 실제 설정·백업 내용을 확인한다.
- 내려받은 파일은 크기와 `sha256sum`으로 빈 응답, 리다이렉션 body 또는 오류 페이지가 아닌지 확인한다.
- 401·403은 경로 존재 후보일 수 있지만 READ 권한은 확인되지 않은 상태다. 200 응답도 custom 오류 페이지와 비교한다.

## 확인할 출력과 권한

- status, length, title과 응답 body를 기준 요청과 비교한다.
- 경로 존재, 파일 READ, 파일 WRITE와 서버 측 실행을 각각 분리한다.
- 401/403이나 입력 파라미터 발견만으로 인가 우회, 주입 또는 SSRF를 단정하지 않는다.

## 변경 영향과 복구

GET·HEAD 기반 경로 열거는 대상 웹 객체를 변경하지 않는다. 다만 `curl -o`를 선택하면 공격 호스트에 `<LOCAL_FILE>`이 생성된다.

1. 다운로드 전 `test ! -e '<LOCAL_FILE>'`로 기존 파일이 없음을 확인하고, 생성 후 URL·Content-Type·크기·SHA-256을 exact 경로와 함께 기록한다.
2. credential·token·설정이 들어 있으면 승인된 보존 위치와 접근 권한을 먼저 적용한다. Vault에 원문을 붙여 넣지 않는다.
3. 분석·인계 뒤 로컬 복사본이 불필요하면 공격 호스트에서 `rm -- '<LOCAL_FILE>'`을 실행하고 `test ! -e '<LOCAL_FILE>'`로 확인한다.

기존 파일을 덮어썼거나 출처 URL·hash를 기록하지 않아 이번 다운로드를 구분할 수 없으면 이름만으로 삭제하지 않는다. 서버 로그와 이미 전송된 민감 정보는 되돌릴 수 없으며, 이 문서의 조회만 수행했다면 대상 서버에 삭제·복원 명령을 실행하지 않는다.
