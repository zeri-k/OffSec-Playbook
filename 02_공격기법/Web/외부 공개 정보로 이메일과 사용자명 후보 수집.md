# 외부 공개 정보로 이메일과 사용자명 후보 수집

## 한 줄 판단

대상 조직명·도메인과 승인된 외부 정찰 범위가 있으면 공개 웹 페이지·문서 metadata·승인된 유출 데이터 소스에서 이메일과 사용자명 형식 후보를 수집하고, 실제 계정 존재와 credential 유효성은 서비스별 열거·인증 단계에서 따로 확인한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | 외부 공개 웹·검색·승인된 데이터 소스에 HTTPS로 연결 가능한 분석 호스트 | 대상 URL의 기준 응답과 외부 서비스 연결 확인 | 프록시·DNS·TLS·rate limit과 대상 서비스 부재를 구분 |
| 현재 계정 또는 인증 수단 | 대상 조직 계정은 불필요하며 유료 API를 쓰면 해당 서비스 계정만 사용 | 실행 전 어떤 외부 서비스 credential이 필요한지 확인 | API credential과 수집 대상 조직 계정을 섞지 않음 |
| 현재 권한 | 계약·RoE와 데이터 소스 이용 조건에서 공개 정보 수집이 허용됨 | 승인된 도메인·수집 방식·보관 범위 확인 | 불명확한 제3자 host·개인정보 조회는 중단하고 범위 확인 |
| 공격 대상의 조건 | 조직 소유 도메인·공개 사이트·문서의 관계가 확인됨 | DNS·등록정보·공식 사이트 링크를 교차 확인 | 같은 IP·이름 유사성만으로 소유 관계를 확정하지 않음 |
| 필요한 파일·목록·주소 | 대상 조직명·도메인, 시작 URL과 작업별 출력 디렉터리 | 기존 경로 부재·CeWL help·ExifTool 존재 확인 | 문서 metadata가 필요하지만 ExifTool이 없으면 이메일·본문 단어 수집만 수행 |

## 실행

### 1. 공개 검색 결과를 후보로 수집

검색 엔진과 조직의 공식 페이지에서 다음 형태의 질의를 사용한다. 검색 결과에 나온 제3자 URL은 소유 관계와 승인 범위를 확인하기 전에는 능동 스캔 대상으로 삼지 않는다.

```text
site:<DOMAIN> "@<DOMAIN>"
site:<DOMAIN> filetype:pdf
site:<DOMAIN> filetype:docx
site:github.com "<DOMAIN>"
```

확인할 출력:

- 공식 연락처·채용·보도 자료에 표시된 이메일 형식과 사용자명 규칙 후보.
- 공개 문서·저장소 URL, 게시 시점과 현재 소유 관계.
- 검색 결과 존재는 현재 URL 접근, 실제 직원 재직, AD·Microsoft 365 계정 존재를 확정하지 않는다.

### 2. 승인된 공개 사이트에서 이메일·단어·문서 metadata 후보 추출

CeWL의 설치 버전이 `-e`·`-a`와 출력 경로 option을 지원하는지 먼저 확인한다. `-a` metadata 수집에는 ExifTool이 필요하다. 대상 웹 서버에 반복 HTTP 요청을 보내므로 승인된 host와 작은 depth에서 시작한다.

```bash
cewl --help
command -v exiftool
CEWL_OUTPUT_DIR="$(mktemp -d "${PWD}/cewl-public.XXXXXX")"
install -d -m 700 "$CEWL_OUTPUT_DIR/meta-temp"
cewl -d '<CRAWL_DEPTH>' -m '<MIN_WORD_LENGTH>' \
  -w "$CEWL_OUTPUT_DIR/words.txt" \
  -e --email_file "$CEWL_OUTPUT_DIR/emails.txt" \
  -a --meta_file "$CEWL_OUTPUT_DIR/metadata.txt" \
  --meta-temp-dir "$CEWL_OUTPUT_DIR/meta-temp" \
  'https://<PUBLIC_HOST>/'
```

확인할 출력:

- `emails.txt`의 이메일 형식 문자열과 반복되는 local-part 규칙.
- `metadata.txt`의 author·creator·사용자명 형태와 해당 공개 문서 URL.
- `words.txt`의 조직명·제품명·부서명 후보. 이 단어는 비밀번호나 계정이 아니다.
- 출력이 비면 후보 부재로 단정하지 않고 redirect·동적 rendering·crawl depth·문서 형식과 ExifTool 오류를 구분한다.

### 3. 승인된 유출 데이터 소스와 교차 확인

유출 데이터 검색이 계약·법률·서비스 약관 범위에서 승인됐고 별도 API 계정이 있으면 [[dehashed.py]]의 현재 API 호환성과 quota를 확인한다. 공개 이메일과 같은 도메인·사용자명 형식이 나타나는 레코드만 후보로 연결한다.

확인할 출력:

- 이메일·사용자명과 유출 시점·출처 데이터베이스 단서.
- 평문 또는 hash가 표시돼도 현재 대상 서비스에서 유효하거나 해당 조직 시스템에서 직접 유출됐다고 확정하지 않는다.
- 외부 API 오류·권한 부족·결과 없음은 서로 다른 상태로 기록한다.

## 변경 영향과 정리

공개 원본은 조회만 하고 수정하지 않는다. CeWL은 `<CEWL_OUTPUT_DIR>`에 wordlist·email·metadata와 임시 문서 사본을 만들 수 있다. 검토·승인된 인계가 끝나면 이번 실행의 고유 경로 안에서 생성된 파일만 정리한다.

```bash
find "$CEWL_OUTPUT_DIR" -xdev -type f -printf '%p %s bytes\n'
rm -f -- "$CEWL_OUTPUT_DIR/words.txt" "$CEWL_OUTPUT_DIR/emails.txt" "$CEWL_OUTPUT_DIR/metadata.txt"
find "$CEWL_OUTPUT_DIR/meta-temp" -xdev -depth -type f -delete
find "$CEWL_OUTPUT_DIR/meta-temp" -xdev -depth -type d -empty -delete
rmdir -- "$CEWL_OUTPUT_DIR"
test ! -e "$CEWL_OUTPUT_DIR"
```

마지막 확인이 실패하면 예상하지 않은 산출물·소유자·열린 프로세스를 먼저 확인하고 재귀 삭제하지 않는다. 대상 access log, 검색·API 제공자의 질의 기록, 이미 전달된 후보와 terminal scrollback은 로컬 파일 삭제로 되돌려지지 않는다. 실제 이메일·사용자명·비밀번호·hash는 Vault에 저장하지 않는다.
