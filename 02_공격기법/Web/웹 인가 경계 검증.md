# 웹 인가 경계 검증

## 한 줄 판단

인증된 요청과 소유자·역할이 다른 테스트 계정 또는 객체가 있으면, 같은 기능의 요청에서 주체·객체 식별자만 한 번에 하나씩 바꿔 응답과 실제 객체 영향을 비교하여 수평·수직 인가 경계를 확인한다.

## 시작 조건 해석


- API path, query, JSON body, form 또는 GraphQL 변수에서 사용자·조직·객체 식별자를 확인했을 때.
- 일반 사용자와 다른 일반 사용자, 또는 일반 사용자와 관리자처럼 비교 가능한 정상 계정을 준비했을 때.
- 읽기 요청을 우선하고, 변경 요청은 전용 테스트 객체와 복구 절차가 있을 때만 확인할 때.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 기준 요청 | 소유자 또는 허용 역할에서 정상 응답을 반환하는 요청 | HTTP method, URL, header, body와 응답을 보존 | 로그인·세션·CSRF·tenant 선택이 정상인지 먼저 확인 |
| 비교 주체 | 소유자·역할·조직이 다른 정상 테스트 계정 | 각 계정으로 자신의 객체 접근을 먼저 확인 | 계정·역할 차이가 없으면 인가 경계를 판정하지 않음 |
| 비교 객체 | 소유 관계가 명확한 테스트 객체 | 객체 ID와 소유자·조직을 기록 | 실제 사용자 데이터나 불명확한 객체를 무작위로 열거하지 않음 |
| 변경 영향 | GET 등 읽기 요청 또는 복구 가능한 전용 테스트 객체 | 요청 method와 서버 측 부작용을 확인 | 상태 변경 요청은 별도 복구 계획을 만든 뒤 제한적으로 확인 |

## 실행

### 1. 허용되는 기준 요청 보존

소유자 계정으로 정상 응답을 받는 요청을 저장한다. 인증 토큰은 파일에 장기 보관하지 않고 실행 시점에 주입한다.

```bash
curl -sS -D owner.headers   -H "Authorization: Bearer <OWNER_TOKEN>"   "https://<HOST>/api/<RESOURCE>/<OWNER_OBJECT_ID>"   -o owner.body
```

확인할 출력:

- 상태 코드, 응답 길이·구조, 반환된 객체 식별자와 소유자 범위.
- 이 응답은 소유자에게 허용된 동작의 기준일 뿐 다른 계정의 권한을 뜻하지 않는다.

### 2. 비교 계정에서 동일 요청 확인

HTTP method·경로·정상 입력을 유지한 채 인증 주체만 비교 계정으로 바꾼다.

```bash
curl -sS -D peer.headers   -H "Authorization: Bearer <PEER_TOKEN>"   "https://<HOST>/api/<RESOURCE>/<OWNER_OBJECT_ID>"   -o peer.body
```

객체 식별자를 바꿔야 한다면 소유 관계가 확인된 두 테스트 객체만 교차 비교한다. 한 번의 요청에서 주체·객체 ID·역할을 동시에 바꾸지 않는다.

### 3. 응답과 실제 영향 판정

```bash
diff -u owner.headers peer.headers
diff -u owner.body peer.body
```

확인할 출력:

- 비교 계정이 소유하지 않은 객체의 실제 내용·다운로드·기능 결과를 받으면 인가 결함 후보가 된다.
- 200 상태 코드, 같은 길이 또는 오류 메시지 차이만으로 접근 성공을 판정하지 않는다. 반환된 객체가 요청한 다른 소유자의 객체인지 확인한다.
- 변경 요청은 전용 테스트 객체에서 변경 전후 상태와 복구를 확인해야 한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 비교 계정이 다른 소유자의 실제 객체 내용을 읽음 | 수평 인가 결함 후보 | 재현 가능한 비인가 읽기 | 영향 객체·조건·증거를 최소 범위로 기록하고 웹 상태 라우터에서 목표 재평가 |
| 일반 사용자가 관리자 전용 동작을 수행함 | 수직 인가 결함 후보 | 재현 가능한 권한 경계 우회 | 영향과 변경 가능 여부를 분리해 확인 |
| 401 또는 403을 반환함 | 해당 요청에서 인가가 거부됨 | 검증한 경계 | 다른 객체·역할·tenant 경계를 섞지 않고 결과 기록 |
| 상태 코드만 달라지고 객체 내용은 확인하지 못함 | 응답 차이만 관찰 | 인가 영향 미확정 | 응답 body, 리다이렉션, 비동기 작업과 실제 객체 상태를 확인 |

## 변경 영향과 복구

| 변경 대상 | 예상 영향 | 검증 방법 | 복구 절차 |
|---|---|---|---|
| 전용 테스트 객체에서 수행한 변경 요청 | 테스트 데이터 상태 변경 | 변경 전후 객체 상태와 감사 로그 확인 | 테스트 객체를 원래 값으로 되돌리고 복구 결과 확인 |
