# 웹 지문 확인과 공격면 분류

## 한 줄 판단

현재 명령 실행 위치에서 대상 HTTP·HTTPS 포트에 연결할 수 있다면, 상태 코드·응답 본문·헤더·TLS 인증서·기술 스택·웹 방화벽 단서를 확인해 올바른 가상 호스트와 다음 열거·인증·공개 exploit 후보를 정한다.

## 시작 조건 해석


- 80/443/8080/8443이 열려 있고 웹 서비스가 확인될 때.
- 제품형 관리 콘솔, CMS, 프레임워크, WAF, 리버스 프록시 여부를 구분해야 할 때.
- 단순 포트 오픈이 아니라 실제 공격면을 좁혀야 할 때.

## 전제 조건

| 조건 | 확인 방법 | 충족 기준 |
|---|---|---|
| 웹 응답 | `curl -I`, 브라우저 | HTTP status/header 확인 |
| TLS 정보 | `openssl s_client` | CN/SAN/인증서 issuer 확인 |
| 기술 스택 | `whatweb`, `nikto`, 수동 확인 | 제품/프레임워크/WAF 단서 |

## 실행

1. `curl`로 status, redirect, header, cookie, server를 확인한다.
2. TLS CN/SAN과 리다이렉션 Host를 확인해 vhost 후보를 만든다.
3. `whatweb`, `wafw00f`, `nikto`로 기술 스택과 위험한 기본 경로를 분류한다.
4. 제품/버전이 명확하면 [[Public Exploit 검토와 검증]]으로 이어간다.

### 명령과 확인할 출력

#### 방식 선택

| 확인할 대상 | 사용할 방식 | 성공 시 얻는 결과 | 실패 시 다음 확인 |
|---|---|---|---|
| HTTP status·header·redirect·cookie | `curl` | 요청한 Host와 scheme의 기본 응답 기준 | HTTP·HTTPS, vhost, redirect loop와 네트워크 오류 구분 |
| HTTPS 인증서의 CN·SAN·issuer | `openssl s_client` | TLS가 제공한 호스트명과 인증서 체인 단서 | SNI 이름, 443/TCP와 TLS 버전 확인 |
| 웹 기술 스택과 제품 지문 | `whatweb` | 응답에서 식별된 CMS·프레임워크·서버 후보 | 추정 지문을 페이지·정적 파일과 교차 확인 |
| 웹 방화벽 단서 | `wafw00f` | 응답 패턴으로 추정한 WAF 제품 후보 | 프록시·CDN과 backend 제품을 구분 |
| 위험한 기본 파일·설정 후보 | `nikto` | 도구가 직접 요청해 구분한 경로·헤더 후보 | 요청량과 차단 여부를 확인하고 수동 요청으로 재현 |

#### 기본 응답 확인

```bash
curl -I http://<TARGET>/
curl -k -I https://<TARGET>/
curl -k -L -v https://<TARGET>/
```

확인할 출력:

- status, redirect, `Server`, `Set-Cookie`, framework header, 인증 요구.
- 연결 실패는 웹 애플리케이션 부재로 해석하지 않고 대상 주소·포트·scheme과 vhost를 확인한다.

#### TLS 인증서 확인

```bash
openssl s_client -connect <TARGET>:443 -servername <HOST>
```

확인할 출력:

- 인증서 CN·SAN·issuer, SNI에 따라 달라지는 인증서와 TLS 협상 오류.
- TLS 협상 성공은 HTTP 경로 접근이나 웹 인증 성공을 뜻하지 않는다.

#### 기술 스택 확인

```bash
whatweb http://<TARGET>/
```

확인할 출력:

- CMS, 프레임워크, 서버와 JavaScript library 후보.
- 단일 header 기반 버전은 추정값으로 기록하고 정적 파일·관리 페이지 등 다른 근거와 교차 확인한다.

#### WAF 단서 확인

```bash
wafw00f http://<TARGET>/
```

확인할 출력:

- WAF 제품 후보와 판정에 사용된 응답 차이.
- WAF 미탐지를 방어 제어 부재로 단정하지 않는다.

#### 기본 파일과 위험 설정 후보 확인

```bash
nikto -h http://<TARGET>/
```

확인할 출력:

- 도구가 요청해 확인한 기본 파일, header와 위험 설정 후보.
- 보고된 경로는 `curl`로 status와 body를 재현한다. 차단·timeout·동일 오류 응답은 취약점 부재와 구분한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 제품명, 버전, 프레임워크, WAF 또는 vhost 후보가 확인된다. | 기술 스택 후보 식별 | 제품·버전 단서 | [[웹 숨은 경로와 민감 파일 열거]]와 [[웹 단서 기반 기능 열거]]에 스택별 입력 반영 |
| 관리자 콘솔, API, Swagger, actuator 또는 기본 경로가 확인된다. | 우선 검증 기능 식별 | 기능 endpoint | 인증 요구, method와 권한별 응답 차이 확인 |
| 공개 exploit 검토에 필요한 정확한 제품과 버전이 확보된다. | exploit 전제 정보 확보 | 공개 exploit 후보 | [[Public Exploit 검토와 검증]]에서 영향 버전과 환경 조건 대조 |
| 403/404만 반환 | Host header/vhost 필요 | 시작 상태 유지 | 인증서 SAN, DNS, vhost brute force |
| WAF/프록시만 보임 | backend 은닉 | 시작 상태 유지 | JS, error page, header 차이, 경로별 응답 |
| 버전 불명 | 보안 header 제거 | 시작 상태 유지 | 정적 파일, changelog, `/server-status`, 공개 exploit 전제 확인 |

## 확인할 출력과 권한

- 판정 기준: HTTP status, redirect, TLS CN·SAN, 제품·버전 근거를 교차 확인하고 추정 버전과 확정 버전을 구분한다.
- 권한 구분: 인증 전·익명·유효 계정 상태를 구분하고, 서비스 응답만으로 실제 권한을 추정하지 않는다.
