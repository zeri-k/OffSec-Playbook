# AD DNS 레코드 열거

## 한 줄 판단

유효한 도메인 계정으로 DC LDAP에 닿고 결과 파일을 쓸 수 있는 실행 호스트가 있으면, AD 통합 DNS zone을 읽어 저장된 내부 호스트명과 IP 대응 관계를 수집하고 직접 검증할 서비스 후보를 얻는다.

## 사용할 때

- 현재 보유 정보: 도메인명, DC 주소 또는 이름, 유효한 도메인 사용자 자격 증명과 필요하면 별칭 후보가 있다.
- 명령 실행 위치와 도달 대상: `adidnsdump`를 실행하고 `records.csv`를 저장할 호스트에서 DC LDAP에 접근할 수 있으며, `-r` 사용 시 해당 호스트에서 DNS 질의도 가능하다.
- 현재 계정과 권한: bind에 사용할 도메인 계정이 AD 통합 DNS zone 하위 객체를 읽을 수 있다. 레코드 읽기는 DNS 레코드 추가·수정 권한을 뜻하지 않는다.
- 지금 가능한 행동과 결과: BloodHound·LDAP 컴퓨터 이름만으로 드러나지 않은 Jenkins, CA, 파일 서버 같은 별칭과 저장된 IP를 연결해 후속 호스트·서비스 확인 대상을 좁힐 수 있다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치와 네트워크 경로 | `adidnsdump` 실행 호스트에서 DC LDAP에 도달하고 `-r` 사용 시 DNS 질의 가능 | DC 이름 해석과 LDAP 연결을 확인하고 작업 디렉터리 쓰기 시험 | LDAP/LDAPS 주소, DNS 서버, 피벗 경로와 방화벽을 각각 확인 |
| 현재 계정 또는 인증 수단 | `<DOMAIN>\<USER>` 형식으로 bind할 유효한 도메인 계정 | 간단한 LDAP bind 또는 `adidnsdump`의 `Bind OK` 확인 | 도메인·사용자 형식, 비밀번호와 계정 상태를 확인 |
| 현재 권한 | AD 통합 DNS zone 및 하위 레코드 읽기 | `Found <N> records`와 `records.csv` 생성 확인 | bind 성공과 zone 읽기 거부를 구분하고 계정의 디렉터리 읽기 범위를 확인 |
| 공격 대상의 조건 | 대상 도메인이 AD 통합 DNS zone을 사용하고 DC가 LDAP로 해당 객체 제공 | 반환된 zone·레코드와 도메인 DN 확인 | DNS가 AD 통합인지, 다른 zone 또는 다른 DC를 조회해야 하는지 확인 |
| 필요한 파일·목록·주소 | DC LDAP URL과 결과 파일을 저장할 경로 | `<DC>`와 현재 작업 디렉터리 확인 | 잘못된 URL scheme, DC 이름 해석과 파일 권한 수정 |

## 실행

### 1. zone 레코드 dump

```bash
adidnsdump -u '<DOMAIN>\<USER>' 'ldap://<DC>'
head records.csv
```

확인할 출력:

- `Bind OK`, `Found <N> records`.
- `records.csv`의 `type,name,value` 열.
- `?`로 남은 값은 아직 resolve되지 않은 레코드다.
- bind 실패 시 계정 형식·자격 증명·LDAP URL을, bind는 성공했지만 파일이 없으면 zone 읽기 권한과 작업 디렉터리 쓰기 권한을 분리해 확인한다.

### 2. 알 수 없는 레코드 resolve

```bash
adidnsdump -u '<DOMAIN>\<USER>' 'ldap://<DC>' -r
rg '^A,' records.csv
```

확인할 출력:

- 이전에 `?`였던 이름에 연결된 A record와 내부 IP.
- `?`가 계속 남으면 DNS 질의 경로, 이름 서버 응답과 레코드 종류를 확인한다. 이 결과만으로 레코드가 존재하지 않는다고 판정하지 않는다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| `Bind OK`와 레코드 파일 생성 | AD DNS 읽기 성공 | 내부 호스트명 목록 | 별칭과 IP를 서비스별로 우선순위화 |
| 의미 있는 별칭과 내부 IP 대응 | 숨겨진 서비스 후보 | 내부 호스트·서비스 단서 | 도달하지 않으면 [[내부망 경로 확보 후 피벗 구성]], 도달하면 해당 서비스 판단 카드 확인 |
| `?` 레코드가 `-r`로 해석됨 | DNS 질의로 값 보강 | 확인된 IP 후보 | 호스트 활성 상태와 서비스 직접 확인 |
| bind 실패 | LDAP 계정 인증, 도메인 형식 또는 연결 문제 | DNS 열거 실패 | 사용자·도메인 표기, DC 주소, LDAP 389·636번과 DNS 53번 연결 확인 |
| 레코드는 있으나 호스트 응답 없음 | 오래된 DNS 또는 현재 비활성 자산 가능 | 미확정 호스트 | 레코드만으로 활성 자산이나 취약성을 단정하지 않음 |

## 확인할 출력과 권한

- 레코드 존재, 이름 해석, 호스트 활성, 서비스 식별을 각각 별도 단계로 판정한다.
- `records.csv`는 AD DNS에 저장된 이름과 값을 확정하지만, 해당 IP가 현재 할당되어 있거나 실행 호스트에서 그 호스트·서비스에 도달할 수 있다는 사실은 확정하지 않는다.
- DNS 별칭은 공격 가능성이나 해당 시스템의 실제 역할을 보장하지 않는다.
