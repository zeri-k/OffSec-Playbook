# 내부망 수동 호스트 식별

## 한 줄 판단

내부 네트워크에 연결된 분석 호스트에서 캡처 권한이 있는 인터페이스를 수동 관찰하여 ARP 송신자와 mDNS·LLMNR·NBT-NS 이름 해석 응답에서 호스트 IP·MAC·이름 후보를 만들고, 능동 확인 전까지 역할과 생존 상태를 미확정으로 유지한다.

## 사용할 때

- 현재 보유 정보: 내부 네트워크에 연결했지만 호스트와 주소 체계를 아직 모른다.
- 명령 실행 위치와 도달성: 관찰 대상 브로드캐스트 도메인에 직접 연결된 Linux 분석 호스트에서 정확한 `<INTERFACE>`를 선택한다. 라우팅 가능한 다른 대역은 같은 범위로 자동 포함되지 않는다.
- 현재 계정과 권한: 대상 호스트 계정은 필요하지 않지만 로컬 인터페이스의 패킷 캡처 권한이 필요하다.
- 지금 가능한 행동과 결과: GUI 사용 여부와 관계없이 트래픽에 응답하지 않는 분석 모드로 관찰 단서를 모은다. 이름 질의의 target과 실제 응답자·송신자를 구분한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 명령 실행 위치 | 내부 네트워크에 연결된 분석 호스트 | `ip -br address`로 호스트 인터페이스와 주소 확인 | 원격 공격 호스트와 내부 분석 호스트를 구분 |
| 네트워크 위치 | `<INTERFACE>`가 관찰할 브로드캐스트 도메인·VLAN에 연결됨 | 인터페이스 주소, route와 대상 CIDR 확인 | 가상·VPN·관리 인터페이스와 대상 인터페이스를 다시 구분 |
| 현재 계정과 권한 | 선택한 인터페이스의 패킷 캡처 권한 | `sudo tcpdump -D` 또는 Wireshark 인터페이스 목록 확인 | 인터페이스 오류와 권한 거부를 분리 |
| 실행 모드 | 패킷을 관찰만 하고 이름 해석 요청에 응답하지 않음 | tcpdump/Wireshark 캡처와 Responder `-A` 표시 확인 | `-A`가 확인되지 않으면 Responder를 시작하지 않음 |
| 결과 기록 범위 | 직접 관찰한 송신자·응답자와 query target을 구분 | 패킷의 source, sender, target과 response 필드 비교 | target-only 주소를 활성 호스트로 기록하지 않음 |

## 실행

### 1. tcpdump로 링크 계층 단서 수집

```bash
sudo tcpdump -ni <INTERFACE> -e 'arp or udp port 5353 or udp port 5355 or udp port 137'
```

확인할 출력:

- ARP 요청·응답의 송신자 IP와 MAC 주소.
- mDNS·LLMNR·NBT-NS 질의에 포함된 호스트명과 질의 대상.
- 같은 주소나 이름이 반복해서 나타나는지 여부.

### 2. Wireshark로 패킷과 이름을 교차 확인

```bash
sudo -E wireshark -i <INTERFACE> -k
```

표시 필터:

```text
arp || mdns || llmnr || nbns
```

확인할 출력:

- ARP의 `Sender IP address`와 `Target IP address`.
- mDNS·LLMNR·NBT-NS의 query name과 응답 주소.
- 관찰한 이름과 IP가 같은 호스트를 가리키는지 여부.

### 3. Responder Analyze 모드로 이름 해석 요청 요약

```bash
sudo responder -I <INTERFACE> -A
```

확인할 출력:

- Analyze 모드가 활성화되었고 poisoning 응답을 보내지 않는 상태.
- LLMNR·NBT-NS·mDNS 요청에서 확인된 호스트명, IP와 도메인 단서.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| ARP 요청·응답의 송신자 IP와 MAC이 반복됨 | 현재 브로드캐스트 도메인에서 실제 프레임을 보낸 호스트 후보 | 내부 호스트 IP 후보 | 후보만 목록화한 뒤 능동 호스트 확인으로 현재 생존 여부 검증 |
| ARP의 Target IP에만 주소가 보이고 응답이 없음 | 누군가 찾고 있는 주소일 뿐 대상의 존재는 미확정 | 탐색 대상 IP 후보 | 활성 호스트로 분류하지 말고 응답 또는 후속 능동 확인 대기 |
| mDNS·LLMNR·NBT-NS 이름과 응답 IP 확인 | 이름과 주소를 연결할 수 있음 | 호스트명·IP 매핑 후보 | DNS 결과와 이후 서비스 스캔에서 이름을 교차 확인 |
| Responder `-A`에 이름 해석 요청 표시 | 수동 분석으로 요청한 이름과 출발지 관찰 | Windows·AD 관련 이름 해석 단서 | 요청 프로토콜과 출발지별로 정리하고 호스트 역할은 필요한 서비스에서 확인 |
| 패킷이 전혀 보이지 않음 | 인터페이스 오류, 조용한 구간 또는 다른 브로드캐스트 도메인 가능성 | 호스트 후보 미확인 | 인터페이스·VLAN·캡처 권한을 다시 확인하고 관찰 시간을 늘림 |
| 예상 범위 밖 주소가 보임 | 라우팅·가상 인터페이스 또는 범위 오인 가능성 | 범위 불명확 | 캡처 인터페이스, route와 대상 CIDR을 재확인하기 전 능동 요청을 보내지 않음 |

## 확인할 출력과 권한

- ARP·이름 해석 패킷에서 직접 본 IP, MAC과 호스트명만 후보로 기록한다.
- ARP 송신자 IP·MAC은 관찰 시점의 링크 계층 활동을 보여 주지만 이후 생존 상태나 열린 서비스를 확정하지 않는다. Target IP만 보인 주소는 활성 호스트 증거가 아니다.
- mDNS·LLMNR·NBT-NS 질의 이름은 요청자가 찾는 이름일 수 있다. 응답 주소나 다른 패킷과 교차 확인하기 전에는 실제 호스트명으로 확정하지 않는다.
- 한 번의 query나 이름만으로 호스트 역할, 운영체제 또는 취약성을 확정하지 않는다.
- Responder는 반드시 `-A` Analyze 모드로 실행되었는지 확인하며, poisoning이나 인증 유도 결과로 해석하지 않는다.
- 수동 캡처로 보이는 범위는 현재 브로드캐스트 도메인에 제한될 수 있다.
