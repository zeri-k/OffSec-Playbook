# SMB 쓰기 가능한 공유 검증

## 한 줄 판단

SMB 클라이언트를 실행할 수 있는 호스트에서 Null·Guest 또는 유효 계정으로 대상 SMB 공유에 도달해 식별 가능한 테스트 파일을 생성·조회·삭제하고, 현재 인증 Identity의 실제 경로별 권한과 파일을 소비하는 실행 주체의 존재를 별도로 확인한다.

## 사용할 때

- 현재 보유 정보: `smbmap` 또는 `netexec --shares`에서 현재 인증 Identity에 `WRITE`로 표시된 공유를 찾았다.
- 명령 실행 위치와 도달성: `smbmap`, `netexec` 또는 `smbclient`를 실행할 수 있는 호스트에서 대상 SMB 서비스와 공유 경로에 도달할 수 있다.
- 현재 계정과 권한: Null·Guest 또는 유효 SMB 계정 중 어떤 Identity로 목록을 얻었는지 알고 있으며, 표시된 공유 권한을 실제 파일 생성으로 검증해야 한다.
- 지금 가능한 행동과 결과: 기존 파일과 겹치지 않는 테스트 파일로 생성·조회·삭제 권한을 확인한다. 배포/share/webroot/logon script 경로처럼 보여도 실행 주체와 trigger를 확인하기 전에는 코드 실행 경로로 확정하지 않는다.

## 실행

### 권한 확인

먼저 현재 인증 Identity가 성공했는지 확인한 뒤, 같은 Identity에 표시되는 공유별 권한을 기록한다.

```bash
smbmap -H <TARGET> -u <USER> -p '<PASSWORD>'
netexec smb <TARGET> -u <USER> -p '<PASSWORD>' --shares
```

확인할 출력:

- share별 `READ, WRITE`.
- 로그인 성공과 `WRITE` 표시는 실제 하위 경로 파일 생성 성공과 별도 상태다.

### 업로드/삭제 확인

검증할 공유와 하위 경로에서만 테스트 파일을 업로드하고, 같은 세션에서 조회와 삭제 가능 여부를 각각 확인한다.

```bash
smbclient //<TARGET>/<SHARE> -U '<USER>%<PASSWORD>'
smb: \> put write-test.txt
smb: \> ls write-test.txt
smb: \> del write-test.txt
```

확인할 출력:

- 업로드, 조회, 삭제 가능 여부.

## 확인할 출력과 권한

- share의 `WRITE` 표시는 현재 인증 Identity에 대한 도구의 권한 해석이며 실제 하위 경로의 생성 성공을 확정하지 않는다.
- 업로드 성공은 해당 경로의 파일 생성만 확정한다. 기존 파일 덮어쓰기, 삭제, 서버 측 실행과 그 실행 주체의 권한은 각각 별도 결과다.
- 웹 루트·배포·logon script·scheduled task처럼 보이는 이름만으로 실행을 단정하지 않고 실제 소비 주체와 trigger를 확인한다.

## 변경 영향과 복구

기존 파일과 겹치지 않는 `<UNIQUE_PROOF>`를 업로드하고 같은 SMB 세션에서 정확한 이름만 삭제한다.

```text
smb: \> del <UNIQUE_PROOF>
smb: \> ls <UNIQUE_PROOF>
```

확인할 출력:

- 삭제 성공 뒤 `<UNIQUE_PROOF>`가 목록에 더 이상 나타나지 않는다.
- 삭제 권한이 없으면 업로드 전에 별도 서버 측 제거 경로를 확인하고, 확인할 수 없다면 proof 파일을 만들지 않는다.
