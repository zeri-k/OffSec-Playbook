# 로컬 관리자 그룹 구성원 추가

## 한 줄 판단

대상 Windows 호스트에서 로컬 `Administrators` 그룹을 변경할 수 있고 추가할 계정을 정확히 식별했다면, 변경 전 구성원을 기록하고 해당 계정 하나만 추가한 뒤 새 로그온의 access token에서 관리자 그룹을 확인한다.

> 로컬 그룹 변경은 새 로그온의 권한을 바꾸며, 기존 세션은 이전 token을 유지할 수 있다. 변경 전 목록에 없던 정확한 계정만 복구에서 제거한다.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 실행 호스트 | 그룹을 변경할 실제 Windows 호스트 | `hostname` | linked server·원격 셸의 실행 위치 재확인 |
| 명령 실행 주체 | 로컬 그룹 변경 권한 보유 | `whoami /all` | SYSTEM·로컬 관리자·위임된 권한을 구분 |
| 추가할 계정 | `<HOST>\<USER>` 또는 `<DOMAIN>\<USER>`를 정확히 식별 | `net user`, 도메인 계정 조회 | 동명이인과 로컬·도메인 계정 혼동 확인 |
| 기준값 | 변경 전 `Administrators` 구성원 목록 | `net localgroup administrators` | 기존 멤버 여부를 확인하지 못하면 추가하지 않음 |
| 새 로그온 경로 | 변경 뒤 새 token을 만들 수 있음 | RDP·WinRM·콘솔 로그온 가능 여부 | 기존 세션만으로 그룹 반영을 판정하지 않음 |

## 실행

### Windows 대상 호스트에서 직접 실행

변경 전 실행 위치·주체와 구성원을 기록한다.

```cmd
hostname
whoami /all
net localgroup administrators
```

대상 계정이 기존 멤버가 아닐 때만 추가한다.

```cmd
net localgroup administrators "<DOMAIN_OR_HOST>\<USER>" /add
net localgroup administrators
```

확인할 출력:

- 명령이 성공하고 변경 후 목록에 정확한 계정이 한 번 표시된다.
- `System error 5` 또는 `Access is denied`가 나오면 명령 실행 성공과 그룹 변경 권한을 구분한다.

### MSSQL linked server의 xp_cmdshell에서 실행

```sql
EXECUTE('EXEC xp_cmdshell ''hostname & whoami /all & net localgroup administrators'';') AT [<LINKED_SERVER>];
EXECUTE('EXEC xp_cmdshell ''net localgroup administrators "<DOMAIN_OR_HOST>\<USER>" /add'';') AT [<LINKED_SERVER>];
EXECUTE('EXEC xp_cmdshell ''net localgroup administrators'';') AT [<LINKED_SERVER>];
GO
```

확인할 출력:

- `hostname`이 변경할 대상 호스트와 일치한다.
- 원격 SQL Server의 OS 실행 주체가 그룹 변경 권한을 가지고 대상 계정이 구성원 목록에 추가된다.

### 새 로그온에서 관리자 token 확인

기존 RDP·PowerShell 세션은 변경 전 access token을 계속 사용한다. 그룹 목록과 기존 token이 다른 이유는 [[Windows 액세스 토큰과 특권 활성화]]의 생성 시점 경계를 따른다. 로그오프한 뒤 새로 로그인한다.

```cmd
shutdown /l
```

새 로그온에서 확인한다.

```cmd
whoami
whoami /groups
net localgroup administrators
```

확인할 출력:

- `whoami`가 추가한 계정과 일치한다.
- `whoami /groups`에 `BUILTIN\Administrators`가 표시된다.
- UAC가 적용되는 원격·대화형 로그온에서는 관리자 그룹 멤버십과 현재 프로세스의 상승 상태를 별도로 확인한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 변경 후 그룹 목록에 계정이 표시됨 | 디렉터리의 로컬 그룹 멤버십 변경 성공 | 로컬 관리자 그룹 멤버십 | 새 로그온으로 token 재발급 |
| 새 로그온의 `whoami /groups`에 관리자 SID가 표시됨 | 대상 계정의 새 관리자 token 확인 | 로컬 관리자 세션 | [[고권한 세션 확보 후 후속 판단]] |
| 추가 명령은 성공했지만 기존 세션 권한이 그대로임 | 기존 access token 사용 중 | 기존 세션 유지 | 로그오프 후 같은 계정으로 재로그인 |
| 새 로그온에서도 관리자 SID가 없음 | 다른 계정·호스트에 추가했거나 token·정책 문제 | 결과 미확정 | `hostname`, 계정 형식과 변경 후 구성원 목록 재확인 |
| `Access is denied` | 현재 실행 주체에 그룹 변경 권한 없음 | 시작 상태 유지 | `whoami /all`과 실제 실행 호스트 확인 |

## 확인할 출력과 권한

- 그룹 목록의 계정 추가와 새 로그온의 관리자 token을 각각 확인한다.
- 로컬 `Administrators` 멤버십, UAC 상승 프로세스와 도메인 권한은 서로 다른 권한 상태다.

## 변경 영향과 복구

변경 전 목록에 없었고 이번 작업에서 추가한 정확한 계정만 제거한다. 제거는 해당 명령 실행 경로를 끄기 전에 수행한다.

```cmd
net localgroup administrators "<DOMAIN_OR_HOST>\<USER>" /delete
net localgroup administrators
```

MSSQL linked server를 사용했다면 같은 대상에서 제거한다.

```sql
EXECUTE('EXEC xp_cmdshell ''net localgroup administrators "<DOMAIN_OR_HOST>\<USER>" /delete'';') AT [<LINKED_SERVER>];
EXECUTE('EXEC xp_cmdshell ''net localgroup administrators'';') AT [<LINKED_SERVER>];
GO
```

- 변경 후 목록에서 해당 계정만 사라지고 기존 구성원이 그대로인지 확인한다.
- 기존 멤버였던 계정은 제거하지 않는다.
- 구성원 제거는 로컬 그룹 상태의 복구다. 이번 추가 뒤 만든 RDP·WinRM·대화형 session은 관리자 SID를 포함한 기존 token을 계속 사용할 수 있으므로 작업 생성 session을 종료한다. 이번 membership이 유일한 관리자 권한 출처였던 경우에는 새 로그온의 `whoami /groups`에서 `BUILTIN\Administrators`가 더 이상 활성 SID가 아닌지 확인해야 권한 영향 정리까지 판정할 수 있다.
