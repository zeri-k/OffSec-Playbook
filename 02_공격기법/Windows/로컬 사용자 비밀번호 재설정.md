# 로컬 사용자 비밀번호 재설정

## 한 줄 판단

대상 Windows 호스트에서 로컬 관리자 또는 SYSTEM 명령을 실행할 수 있다면, 지정한 로컬 사용자의 비밀번호를 임시 값으로 재설정하고 그 호스트의 로컬 계정 인증 범위만 확인한다.

## 사용할 때

- SYSTEM 명령 실행은 가능하지만 대화형 로그인이나 SMB 파일 접근에 사용할 로컬 자격 증명이 필요할 때.
- AD 사용자 변경이 아니라 현재 Windows 호스트의 SAM에 있는 로컬 사용자만 변경할 때.
- 비밀번호 변경으로 기존 서비스·예약 작업·자동 로그온이 중단될 수 있음을 확인한 뒤 사용할 때.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 실행 호스트와 권한 | 목표 호스트의 상승된 관리자 또는 SYSTEM | `hostname & whoami /all` | 일반 사용자 token이면 다른 권한 상승 기법 선택 |
| 대상 계정 범위 | 로컬 SAM 사용자 | `net user <LOCAL_USER>` | 도메인 사용자이면 [[AD 사용자 비밀번호 강제 재설정]]으로 분리 |
| 정책·계정 상태 | 임시 비밀번호가 정책을 충족하고 계정이 사용 가능 | `net accounts`, `net user` | 잠금·비활성·로그온 제한 확인 |
| 복구 | 원래 값을 알고 있거나 관리자가 재설정할 계획 | 변경 전 영향 기록 | 원래 값을 모르면 자동 원복 불가 |

## 실행

### 1. 대상 Windows 호스트에서 기존 상태 확인

비밀번호 값 자체를 기록하지 말고 계정 상태와 이 계정을 사용하는 구성 요소만 작업 기록에 남긴다. 서비스·예약 작업·자동 로그온에서 대상 계정을 사용한다면 해당 담당자와 복구 방법을 먼저 정한다.

```powershell
hostname
whoami /all
net user <LOCAL_USER>
Get-CimInstance Win32_Service | Where-Object StartName -match '(^|\\)<LOCAL_USER>$' | Select-Object Name, StartName, State
Get-ScheduledTask | Where-Object { $_.Principal.UserId -match '(^|\\)<LOCAL_USER>$' } | Select-Object TaskPath, TaskName, State
```

원래 비밀번호를 알고 있는 경우에도 Vault나 명령 기록에 저장하지 않는다. 원래 비밀번호를 모르면 이번 변경 전 상태로 자동 복원할 수 없으므로, 승인된 관리자가 새 관리 비밀번호를 설정하고 종속 구성을 갱신할 계획이 없으면 실행하지 않는다.

### 2. 계정 재설정

```cmd
net user <LOCAL_USER>
net user <LOCAL_USER> <TEMP_PASSWORD>
```

### 3. Linux 공격 호스트에서 로컬 계정 인증 확인

```bash
netexec smb <TARGET> --local-auth -u <LOCAL_USER> -p '<TEMP_PASSWORD>'
smbclient //<TARGET>/C$ -W WORKGROUP -U '<LOCAL_USER>%<TEMP_PASSWORD>' -c 'ls'
```

확인할 출력:

- `The command completed successfully.`는 비밀번호 변경 명령 완료를 뜻한다.
- `netexec` 인증 성공과 `smbclient`의 실제 공유 접근은 별도 결과다.
- `C$` 접근 실패만으로 비밀번호가 틀렸다고 판단하지 말고 인증 성공·관리 공유 권한·UAC 원격 제한을 분리한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 변경 완료와 로컬 인증 성공 | 대상 호스트의 로컬 자격 증명 확보 | 로컬 사용자명·임시 비밀번호 | 원복 후 [[확보한 자격 증명으로 원격 접근 경로 선택]] |
| 변경 완료이나 SMB 공유 접근 거부 | 자격 증명은 유효할 수 있으나 공유 권한 부족 | 로컬 인증 후보 | SMB 인증 결과와 UAC·관리 공유 권한을 따로 확인 |
| 계정 없음 | 로컬·도메인 계정 범위 또는 사용자명 오류 | 변경 없음 | `net user`, `whoami /user`와 도메인 표기 확인 |
| 비밀번호 정책 오류 | 임시 값이 로컬 정책을 충족하지 않음 | 변경 없음 | `net accounts` 결과에 맞는 임시 값 선택 |

## 확인할 출력과 권한

- 로컬 비밀번호 변경은 해당 호스트의 SAM 계정에만 적용된다.
- 로컬 관리자 그룹 멤버십과 원격 UAC 제한 때문에 인증 성공, 관리 공유 접근과 원격 명령 실행 결과가 달라질 수 있다.

## 변경 영향과 복구

대상 Windows 호스트의 상승된 관리자 셸에서 복구한다.

### 원래 비밀번호를 알고 있고 정책상 재사용이 허용되는 경우

```cmd
net user <LOCAL_USER> <ORIGINAL_PASSWORD>
net user <LOCAL_USER>
```

명령 성공 후 작업 전에 기록한 서비스와 예약 작업 상태를 다시 확인하고, 승인된 최소 한 개 인증 경로에서 계정 사용 가능 여부를 확인한다. 원래 문자열을 다시 설정해도 이미 끊긴 세션, 기록된 감사 이벤트와 그 사이 발생한 종속 자격 증명 갱신까지 되돌리지는 못하므로 이를 완전한 시점 복원으로 표현하지 않는다.

### 원래 비밀번호를 모르는 경우

자동 원복은 불가능하다. 계정 소유자 또는 승인된 관리자가 새 관리 비밀번호를 설정하고, 작업 전에 식별한 서비스·예약 작업·자동 로그온의 저장 자격 증명을 갱신한 뒤 각 구성 요소의 정상 동작을 확인해야 한다. 이 확인이 끝나기 전에는 `복구 완료`가 아니라 `관리자 복구 인계`로 기록한다. 비밀번호 값은 Vault에 남기지 않는다.

첫 복구 명령이 정책 오류로 실패하면 반복 재설정하지 말고 `net accounts`와 `net user <LOCAL_USER>`에서 비밀번호 기록·계정 제한을 먼저 확인한다. 계정 상태나 종속 서비스가 기준선과 다르면 담당자에게 정확한 계정명과 실패 출력을 인계한다.
