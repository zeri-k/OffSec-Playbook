# wafw00f

## 도구 개요

`wafw00f`는 정상 요청과 탐지용 요청의 HTTP 응답 차이를 WAF(Web Application Firewall) 서명과 비교해 앞단 필터와 제품 후보를 식별한다. 웹 정찰 초기에 WAF 개입 여부와 응답 변형 가능성을 파악할 때 유용하지만, 제품 탐지나 미탐지만으로 실제 차단 정책 또는 WAF 부재를 확정하지 않는다.

## 필요한 입력과 실행 환경

- 실행 위치와 도달성: `wafw00f`가 설치되어 있고 대상 HTTP(S) 포트까지 연결할 수 있는 Linux 호스트
- 대상 URL: 스킴, 포트, 가상 호스트와 기준 경로를 포함한 URL. IP와 domain의 응답이 다르면 의도한 vhost URL을 사용하고 DNS·Host·TLS SNI를 맞춘다.
- 필요한 인증 정보: 아래 예시는 익명 응답을 비교한다. 로그인 뒤 경로와 역할별 WAF 정책은 인증 상태를 전달하지 않으면 관찰되지 않을 수 있다.
- 선택 입력: proxy, 출력 형식과 대상 목록
- 대상에서 필요한 서비스와 권한: 정상 요청과 탐지용 요청에 HTTP 응답이 있어야 한다. `401`·`403`·redirect 수신은 서비스 도달을 뜻할 수 있지만 애플리케이션 인증 성공이나 WAF 차단을 단독으로 확정하지 않는다.


## 표준 사용법

```bash
wafw00f <url_or_domain>
```

스킴을 생략하면 기본 웹 요청으로 탐지하고, HTTPS 여부가 중요하면 `https://`를 명시한다.

## 대표 예시

### WAF 존재 여부 확인

```bash
wafw00f <DOMAIN>
```

대상 앞단에 WAF가 있는지와 어떤 제품으로 보이는지 확인한다.

확인할 출력:

- 제품 탐지 시 `is behind ... WAF` 형태의 제품명·vendor 신호가, 미탐지 시 WAF를 식별하지 못했다는 결과가 나오는지 확인한다.
- 제품명은 응답 signature 일치 결과다. 실제 배치 위치, 정책과 우회 가능성은 확정하지 않는다.

### HTTPS 대상으로 확인

```bash
wafw00f https://<DOMAIN>
```

리디렉션이나 HTTPS 전용 사이트에서 명확하게 HTTPS 엔드포인트를 지정한다.

확인할 출력:

- HTTPS 대상에서 TLS 연결 뒤 탐지 결과가 나오는지 확인한다. HTTP URL의 redirect 결과와 최종 HTTPS 응답은 서로 다른 탐지 조건일 수 있다.

### 상세 출력으로 탐지 근거 확인

```bash
wafw00f -v https://<DOMAIN>
```

탐지 과정과 응답 차이를 더 자세히 확인한다.

확인할 출력:

- 상세 로그에서 요청 단계와 응답 차이, 적용된 탐지 신호를 확인한다. 단일 `403`은 인증·애플리케이션·proxy 정책일 수도 있으므로 WAF 근거와 분리한다.

### 여러 WAF 후보 모두 확인

```bash
wafw00f -a https://<DOMAIN>
```

첫 번째 탐지에서 멈추지 않고 가능한 모든 WAF fingerprint를 확인한다.

확인할 출력:

- 둘 이상의 제품·generic signature가 보고되는지 확인한다. 여러 결과는 CDN·reverse proxy·WAF 계층 또는 signature 중복 후보이며 모두 실제 제품이라고 단정하지 않는다.

### 결과 파일 저장

```bash
wafw00f -o wafw00f.json -f json https://<DOMAIN>
```

결과를 JSON으로 저장해 이후 비교와 요청 방식 조정에 활용한다.

확인할 출력:

- `wafw00f.json`이 생성되고 대상 URL과 탐지 결과가 JSON으로 기록되는지 확인한다. 파일 생성만으로 대상별 모든 요청이 성공했다고 판단하지 않고 오류 필드와 종료 상태를 함께 본다.

## 주요 옵션

| 옵션 | 의미 | 사용하는 상황 |
| --- | --- | --- |
| `-v` | 탐지 과정과 요청·응답 정보를 상세 출력 | 제품명만으로 근거가 부족하거나 차단·인증 응답을 구분할 때 |
| `-a` | 첫 일치 뒤에도 가능한 WAF 탐지를 모두 수행 | CDN·reverse proxy·WAF의 복수 signature를 비교할 때 |
| `-r` | 리디렉션을 따라가지 않음 | 최초 URL과 redirect 목적지의 앞단 처리를 분리할 때 |
| `-p <proxy>` | 프록시를 통해 요청 전송 | 지정 network path 또는 request inspection이 필요할 때 |
| `-o <file>` | 결과 파일 저장 | 대상·탐지 결과를 후속 비교용으로 남길 때 |
| `-f <format>` | 출력 형식 지정. 예: `json`, `csv`, `text` | 사람이 읽거나 다른 도구로 처리할 형식을 고를 때 |
| `-i <file>` | 대상 목록 파일 입력 | 여러 URL을 같은 조건으로 검사할 때 |
| `-l` | 지원 WAF 탐지 플러그인 목록 출력 | 현재 버전이 식별할 수 있는 제품 범위를 확인할 때 |
| `--timeout <sec>` | 요청 타임아웃 지정 | 느린 응답과 연결 실패를 구분할 수 있게 대기 시간을 조정할 때 |


## 도구 고유 출력

| 출력·상태 | 의미 | 확정 범위와 다음 확인 |
|---|---|---|
| `is behind <PRODUCT> WAF` 형태의 제품 탐지 | 응답이 해당 WAF plugin signature와 일치함 | 제품 후보만 확정한다. 정상·탐지용 요청을 비교해 실제 차단 동작, 적용 경로와 false positive를 검증한다. |
| generic WAF 탐지 | 제품 plugin은 불명확하지만 응답 차단·변형 신호가 관찰됨 | 앞단 필터 후보로 유지하고 status, header, body와 request ID 차이를 수동 비교한다. |
| WAF 미탐지 결과 | 현재 URL·요청·plugin 범위에서 명확한 signature 미확인 | WAF 부재나 비활성화를 확정하지 않는다. 인증 상태, 다른 경로와 응답 변화는 계속 확인한다. |
| `401`, `403`, redirect만 반복 | 인증·인가·애플리케이션 또는 앞단 정책 때문에 기준 응답이 제한될 수 있음 | 단독 WAF 신호로 사용하지 말고 정상 브라우저 요청과 비교한다. |
| 연결·이름 해석·TLS·timeout 오류 | 탐지 요청을 완료하지 못함 | WAF 미탐지와 구분하고 `curl`, URL의 vhost, proxy와 TLS 설정을 확인한다. |
