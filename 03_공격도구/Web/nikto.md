# nikto

## 도구 개요

`nikto`는 HTTP(S) 서비스에서 알려진 파일, 위험 설정, 배너와 보안 헤더 서명을 자동 점검하는 웹 서버 스캐너다. 웹 서버의 흔한 노출과 설정 문제를 넓게 선별해 수동 검증 대상을 만들 때 적합하며, `+` finding 자체는 취약성이나 exploit 가능성을 확정하지 않는다.

## 필요한 입력과 실행 환경

- 실행 위치와 도달성: `nikto`를 실행할 수 있고 대상 HTTP(S) 포트까지 연결할 수 있는 Linux 호스트
- 대상 URL·vhost: 스킴, 포트, 기준 경로와 가상 호스트를 포함한 URL 또는 host. IP만 지정하면 기본 vhost를 검사할 수 있으므로 redirect, Host와 TLS SNI가 의도한 애플리케이션을 가리키는지 먼저 확인한다.
- 필요한 인증 정보: 익명 검사가 기본이다. 보호된 경로에는 대상이 지원하는 인증 방식에 맞는 유효한 인증 정보가 필요하며, 아래 `-id` 예시는 `user:pass` 형식의 단순 HTTP 인증을 전달한다.
- 선택 입력: 검사 범위(`-Tuning`), 대상 포트, TLS 사용 여부, 출력 파일과 형식
- 대상에서 필요한 서비스와 권한: HTTP 연결 후 응답을 읽을 수 있어야 한다. `401`·`403` 수신은 서비스 도달을 뜻할 수 있지만 인증 성공이나 해당 경로의 읽기 권한을 뜻하지 않는다.
- 실행 특성: 다수의 HTTP 요청을 순차적으로 전송하므로 응답 지연, WAF와 rate limit의 영향을 받는다.

## 표준 사용법

```bash
nikto -h <host_or_url>
```

HTTPS, 포트, 인증, 출력 파일 등은 옵션으로 지정한다.

## 대표 예시

### 기본 웹 서버 점검

```bash
nikto -h http://<TARGET>
```

대상 웹 서버의 흔한 취약 파일, 설정 오류, 서버 정보 노출을 확인한다.

확인할 출력:

- `+ Target Hostname`, `+ Target Port`, `+ Start Time`이 의도한 대상과 일치하는지 확인한다.
- `+ Server:`와 `+ /경로: ...` finding은 응답 기반 단서다. 제품·버전과 파일 내용, 실제 영향은 수동 요청으로 검증한다.

### 소프트웨어 식별 모듈만 실행

```bash
nikto -h <DOMAIN> -Tuning b
```

`-Tuning b`는 소프트웨어 식별 중심으로 검사 범위를 줄일 때 사용한다.

확인할 출력:

- 서버·미들웨어·기술 식별 finding이 출력되는지 확인한다. 배너와 서명 기반 버전은 후보이며 실제 설치 버전이나 취약 패치 상태를 확정하지 않는다.

### HTTPS 포트 점검

```bash
nikto -h <TARGET> -p 443 -ssl
```

443 포트에서 TLS를 사용하는 웹 서비스를 점검한다.

확인할 출력:

- 대상 포트가 `443`으로 표시되고 TLS handshake 뒤 HTTP finding이 이어지는지 확인한다.
- TLS 연결 성공은 인증된 애플리케이션 접근이나 취약성 존재를 의미하지 않는다.

### 특정 포트 여러 개 점검

```bash
nikto -h <TARGET> -p 80,8080,8443
```

같은 호스트의 여러 웹 포트를 한 번에 확인한다.

확인할 출력:

- 각 포트의 target·start·end 구간과 finding을 분리해 확인한다.
- 열린 포트가 모두 같은 HTTP 프로토콜·vhost를 사용한다고 가정하지 말고 HTTPS 포트는 `-ssl` 또는 명시적 HTTPS URL로 별도 확인한다.

### 인증이 필요한 경로 점검

```bash
nikto -h http://<TARGET>/admin -id admin:<PASSWORD>
```

Basic 인증 등 단순 인증이 필요한 영역을 점검할 때 사용한다.

확인할 출력:

- 인증 전 `401` 응답과 달리 보호 경로의 콘텐츠·finding이 반환되는지 확인한다.
- `401`·`403`이 계속되면 HTTP 연결만 성공한 것이며 자격 증명 유효성이나 경로 권한은 확인되지 않은 상태다.

### 결과 저장

```bash
nikto -h http://<TARGET> -o nikto.txt -Format txt
```

결과를 파일로 저장해 이후 수동 검증이나 재스캔 비교에 사용한다.

확인할 출력:

- `nikto.txt`가 생성되고 target 정보, finding과 스캔 종료 요약이 기록되는지 확인한다. 파일 생성만으로 모든 test가 완료됐다고 판단하지 말고 종료 상태를 함께 본다.

## 주요 옵션

| 옵션 | 의미 | 사용하는 상황 |
| --- | --- | --- |
| `-h <host>` | 대상 호스트 또는 URL | 스킴·vhost·기준 경로를 포함한 검사 대상을 정할 때 |
| `-p <port>` | 대상 포트. 여러 포트 지정 가능 | 기본 포트가 아니거나 같은 호스트의 여러 웹 포트를 볼 때 |
| `-ssl` | SSL/TLS로 HTTP 요청 전송 | 지정 포트의 서비스가 HTTPS일 때 |
| `-Tuning <value>` | 검사 범위 조정. 예: `b`는 software identification | 전체 검사 대신 필요한 test 종류만 실행할 때 |
| `-id <user:pass>` | 대상 HTTP 인증 정보 지정 | 익명 응답과 인증 후 응답 범위를 분리해 검사할 때 |
| `-o <file>` | 결과 파일 저장 | finding과 당시 대상 설정을 후속 검증용으로 남길 때 |
| `-Format <format>` | 출력 형식 지정. 예: `txt`, `csv`, `html`, `xml` | 사람이 읽거나 다른 도구로 처리할 형식을 선택할 때 |
| `-useragent <ua>` | User-Agent 지정 | 기본 User-Agent 차단 여부와 응답 차이를 확인할 때 |
| `-nointeractive` | 비대화형 실행 | 자동화 환경에서 입력 대기 없이 종료 상태를 받을 때 |


## 도구 고유 출력

| 출력·상태 | 의미 | 확정 범위와 다음 확인 |
|---|---|---|
| `+ Target Hostname`, `+ Target Port`, `+ Start Time` | Nikto가 해당 대상 설정으로 검사를 시작함 | 대상·포트 선택만 확정한다. vhost·인증 상태가 맞는지 redirect와 응답을 확인한다. |
| `+ Server:` 또는 제품·버전 finding | 응답 배너·서명이 특정 제품이나 버전과 일치함 | 지문 후보만 확정한다. 실제 버전, patch와 공개 exploit 전제는 vendor 정보와 수동 응답으로 교차 확인한다. |
| `+ /<PATH>: ...` 위험 파일·기본 파일 finding | 해당 요청이 Nikto test signature와 일치하는 응답을 반환함 | 경로·본문·인증 상태를 `curl`·브라우저로 재현한다. 파일 READ나 취약성은 finding만으로 확정하지 않는다. |
| 보안 헤더 누락 finding | 검사한 응답에서 해당 헤더를 관찰하지 못함 | 해당 응답의 방어 설정만 의미한다. 곧바로 악용 가능한 취약성으로 분류하지 않는다. |
| `401`, `403`, redirect 또는 WAF 응답이 반복됨 | 서비스에는 도달했지만 익명·현재 인증 상태에서 원본 콘텐츠가 제한됨 | 인증 정보, 최종 URL, vhost와 정상·차단 응답을 비교한다. |
| 연결·이름 해석·TLS 오류 또는 비정상 종료 요약 | 대상 요청이나 일부 test가 완료되지 않음 | 결과 없음과 구분하고 스킴, 포트, DNS, TLS, rate limit을 수정한 뒤 종료 상태를 다시 확인한다. |
