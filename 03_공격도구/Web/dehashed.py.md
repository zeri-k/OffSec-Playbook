# dehashed.py

## 도구 개요

`dehashed.py`는 DeHashed API에서 조직 도메인과 연관된 이메일·사용자명·비밀번호·hash 유출 후보를 수집하는 스크립트다. 외부 정찰에서 사용자명 형식과 자격 증명 후보를 만들 때 사용하며, 대상 조직의 서버에 직접 접속하거나 현재 계정 존재와 인증 성공을 확인하는 도구는 아니다.

## 필요한 입력과 실행 환경

- 실행 위치와 도달성: Python 3로 `dehashed.py`를 실행할 수 있고 DeHashed API의 HTTPS 서비스에 연결할 수 있는 Linux 호스트
- 필요한 파일·값: `dehashed.py`, 조회할 조직 도메인, 스크립트가 요구하는 형식의 유효한 DeHashed API 계정·API key
- 대상 구분: `<DOMAIN>`은 DeHashed 데이터의 검색 문자열이다. 이 명령은 대상 조직의 웹 서버, 도메인 컨트롤러 또는 인증 포털에 직접 연결하지 않는다.
- 필요한 인증 정보: DeHashed API 인증 정보만 필요하다. 수집된 조직 계정 후보는 API 인증 정보와 별개이며 아직 검증되지 않은 값이다.
- 대상 서비스와 권한: API 계정에 해당 검색과 비밀번호 관련 필드를 조회할 권한·quota가 있어야 한다. `sudo`는 로컬 스크립트 실행 권한일 뿐 대상 조직 권한을 의미하지 않는다.

## 표준 사용법

```bash
sudo python3 dehashed.py -q <DOMAIN> -p
```

## 대표 예시

```bash
sudo python3 dehashed.py -q example.local -p
```

확인할 출력:

- `email`, `username`, `password`, `hashed_password` 필드.
- `database_name`으로 표시되는 유출 출처 단서.
- 레코드가 반환되면 해당 문자열이 DeHashed 검색 결과에 존재한다는 점만 확정한다. 대상 AD의 현재 계정 상태, 비밀번호 유효성, 잠금 정책과 접근 권한은 확정하지 않는다.
- API 인증·quota 오류나 Python 예외가 나오면 조직 데이터 부재가 아니라 조회 실패로 분류한다.

## 주요 옵션

| 옵션 | 의미 | 사용하는 상황 |
|---|---|---|
| `-q <DOMAIN>` | 검색할 도메인 질의 | 특정 조직 도메인으로 결과 제한 |
| `-p` | 비밀번호 관련 필드 포함 | API 권한과 승인 범위 안에서 credential 후보를 함께 확인할 때 |

## 도구 고유 출력

| 출력·상태 | 의미 | 다음 확인 |
|---|---|---|
| `id`, `email`, `username` 레코드 | 질의와 일치한 유출 데이터 레코드 및 사용자명 형식 후보 | DeHashed 내 문자열 일치만 확정한다. [[인증 전 AD 사용자 목록 수집]]에서 실제 AD 계정 여부를 확인한다. |
| `password`, `hashed_password` | 과거 유출 평문 비밀번호 또는 password hash 후보 | 현재 유효성은 확정되지 않는다. 최신성을 검토하고 인증 검증 전 잠금 정책과 rate limit을 확인한다. |
| `database_name` | 값이 포함된 유출 데이터 출처 단서 | 대상 조직의 현재 시스템에서 유출됐다는 뜻은 아니다. 시점·도메인 관련성·오탐 가능성을 검토한다. |
| 레코드가 출력되지 않음 | 해당 질의와 API가 반환한 범위에서 데이터 미확인 | 계정이나 유출 이력 부재로 단정하지 않고 질의 형식, API 권한과 검색 범위를 확인한다. |
| HTTP `401`·`403`, quota·rate limit 오류 또는 Python 예외 | API 인증·권한·호환성 문제로 조회 실패 | 결과 없음과 구분하고 API key, 계정 권한, 현재 API 문법과 스크립트 호환성을 확인한다. |

## 버전과 환경 차이

- 기존 스크립트는 DeHashed API 구조 변경으로 수정이 필요할 수 있다. 실행 전 현재 스크립트의 API 문법과 출력 필드를 확인한다.
