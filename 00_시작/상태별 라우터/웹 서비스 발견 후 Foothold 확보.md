# 웹 서비스 발견 후 Foothold 확보

## 상태 라우터 개요

웹 서비스가 보이면 호스트·경로·기능·제품 단서를 좁히고, 실제 쓰기나 명령 실행이 재현된 경로만 초기 접근으로 전환한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | 웹 애플리케이션이며 서버 OS는 미확인 가능 |
| 현재 계정 | 인증 전 또는 확보한 웹 계정 |
| 현재 가능한 행위 | HTTP·HTTPS·WebDAV·API 요청 전송과 웹 기능 조작 |
| 현재 권한 | 익명 또는 웹 애플리케이션 사용자 권한 |
| 보유 정보 | URL과 확인된 호스트·제품·기능 단서 |
| 네트워크 위치 | 웹 서비스에 직접 또는 피벗 경유 접근 가능 |
| 목표 | 취약 동작을 검증하고 제한된 명령 실행 또는 셸 확보 |

## 판단 경로

|---|---|---|---|---|
| HTTP·HTTPS endpoint에 연결할 수 있지만 제품·프레임워크·redirect 대상·인증 경계가 불명확함 | [[웹 지문 확인과 공격면 분류]] | 제품·프레임워크·호스트 후보 | 이 상태 라우터 재평가 | 요청한 Host·SNI·URL이 대상 서비스와 일치하는지, redirect 뒤 응답과 인증 경계를 확인 |
| hostname·vhost 후보가 있고 Host·SNI·경로별 애플리케이션과 유효 경로를 아직 매핑하지 않음 | [[웹 정찰과 경로 열거]] | vhost·애플리케이션·유효 경로 | 이 상태 라우터 재평가 | DNS·Host 헤더·TLS SNI, 상태 코드와 현재 위치에서 대상 포트 도달성을 확인 |
| 웹 콘텐츠에는 접근할 수 있지만 숨은 경로·백업·설정 파일을 아직 열거하지 않음 | [[웹 숨은 경로와 민감 파일 열거]] | 인증·설정·파일 단서 | 자격 증명이면 [[확보한 자격 증명으로 원격 접근 경로 선택]], 그 외에는 이 상태 라우터 재평가 | 기준 응답·상태 코드, 접근 제어, 사전 목록의 범위와 속도 제한을 확인 |
| JavaScript·API·폼·업로드 기능은 확인했지만 입력·인증·파일 처리 동작을 아직 매핑하지 않음 | [[웹 단서 기반 기능 열거]] | 검증할 입력·인증·파일 처리 지점 | 이 상태 라우터에서 입력별 기법 재선택 | 요청이 실제 백엔드에 도달하는지, 인증·권한 경계와 입력 검증·파일 처리 규칙을 확인 |
| 제품·버전과 공개 exploit 후보가 있지만 대상 구성과 exploit 전제 조건을 아직 검증하지 않음 | [[Public Exploit 검토와 검증]] | 재현 가능한 취약 후보 또는 제외 근거 | 이 상태 라우터에서 실제 결과 상태 재평가 | 정확한 제품·버전·구성, 인증 필요 여부, 대상 endpoint와 검증 조건을 확인 |

| 웹 애플리케이션에 파일 업로드 기능이 있지만 저장 경로·노출 URL·서버 측 실행 여부가 미확인임 | [[웹 파일 업로드와 Web Shell]] | 업로드 파일의 서버 측 실행 또는 제한된 Web Shell | 쓰기만 확인되면 이 상태 라우터, 셸이면 플랫폼별 셸 상태 라우터 | 파일 검증·저장명·저장 경로, 접근 URL, 실행 handler와 WAF 동작을 확인 |
| 대상 서버에서 단일 명령 실행을 확인했고 안정적인 대화형 세션이 필요함 | [[Reverse Shell 획득]] | 제한된 셸 또는 세션 | Linux는 [[Linux 셸 확보 후 초기 열거와 권한 상승]], Windows는 [[Windows 셸 또는 세션 확보 후 컨텍스트 열거]] | 명령이 대상 서버에서 실행되는지, 실행 사용자·OS·egress 경로와 세션 수신 위치를 확인 |

## 상태 재평가

- 로그인 화면, 파일 쓰기, 웹 접근 가능 파일과 서버 측 실행을 서로 다른 상태로 구분한다.
- `403`, redirect와 업로드 성공만으로 취약점 또는 코드 실행을 단정하지 않는다.
- 셸을 얻으면 대상 플랫폼, 실행 사용자, 네트워크 위치와 셸 품질을 다시 확인한다.
- 새 평문 비밀번호·password hash·API token·개인키가 생기면 웹 로그인과 다른 원격 서비스 인증 가능성을 분리해 검증한다.
- 실제 셸, 계정명이 연결된 비밀번호·hash·token·key 또는 고권한이 확인되면 웹 라우터보다 해당 결과 상태 라우터를 우선한다.
