# AD Identity 확인 후 도메인 컨텍스트 열거

## 상태 라우터 개요

AD 계정을 확인하면 도메인·DC·DNS·시간·서비스 도달성을 먼저 확정하고, 현재 계정이 실제로 읽거나 사용할 수 있는 사용자·그룹·SPN·객체 권한만 다음 기법으로 연결한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | AD와 통합된 Windows 또는 Linux, 또는 AD 서비스 |
| 현재 계정 | 도메인 사용자·서비스 계정·머신 계정·Kerberos 계정 |
| 현재 가능한 행위 | 도메인 세션에서 명령 실행, 계정의 평문 비밀번호·NT hash·AES key·Kerberos ticket을 지원하는 원격 서비스에 인증 |
| 현재 권한 | 현재 사용 중인 계정의 기본·그룹·객체 권한을 별도 확인 |
| 보유 정보 | 현재 AD 계정 컨텍스트 또는 계정명이 확인된 비밀번호·NT hash·AES key·Kerberos ticket, 도메인·DC 단서 |
| 네트워크 위치 | DC의 필요한 서비스에 직접 또는 피벗 경유 접근 가능 |
| 목표 | 도메인 컨텍스트와 실제 권한을 확정해 후속 AD 기법 선택 |

## 상태 재평가

- 도메인 조인 호스트, 현재 로그온 계정과 사용 중인 Kerberos 계정을 같은 것으로 가정하지 않는다.
- 그룹 멤버십, 로컬 관리자, 원격 로그인 권한, AD 객체 권한과 복제 권한을 각각 구분한다.
- Kerberos 실패는 계정 비밀번호·key·ticket뿐 아니라 DNS, FQDN, realm, 시간과 피벗 경로를 함께 확인한다.
- 새 계정의 평문 비밀번호·NT hash·AES key·Kerberos ticket, 객체 권한, 세션 또는 네트워크 위치를 얻으면 해당 상태 라우터로 전환한다.
- 동시에 성립하는 상태를 버리지 않는다. AD 객체·권한 관계가 목표면 이 라우터를, 인증 자료의 사용처가 목표면 [[확보한 자격 증명으로 원격 접근 경로 선택]]을, 현재 호스트의 실행 환경·로컬 권한이 목표면 플랫폼 라우터를, 다른 대역 도달성이 목표면 [[내부망 경로 확보 후 피벗 구성]]을 선택한다.
- 같은 목표·상태의 명령·기법 실패는 연결된 기법 문서의 실패 분기와 이 라우터에서 처리한다. 목표가 바뀌거나 계정·권한·가능한 행위·네트워크 위치가 바뀌어 다음 라우터가 불명확하면 [[Playbook|홈]]으로 돌아가 상태와 목표를 함께 다시 고른다.
- DNS, 계정 위험 속성, SYSVOL·GPP, LAPS, 원격 접근 권한, GPO와 Spooler 같은 상세 열거 분기는 [[Active Directory 플레이북]]에서 고른다.
