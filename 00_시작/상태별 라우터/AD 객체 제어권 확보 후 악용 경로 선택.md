# AD 객체 제어권 확보 후 악용 경로 선택

## 상태 라우터 개요

ACL이나 BloodHound에서 제어 경로를 찾으면 현재 계정이 어떤 AD 객체에 어떤 권한을 행사할 수 있는지 확인한다. 이후 비밀번호 재설정, 그룹 구성원 추가, SPN 설정처럼 확인한 권한에 직접 대응하는 기법을 선택하고, 변경 전 원래 값과 복구 방법을 확인한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | Active Directory Domain Services |
| 현재 계정 | ACL을 행사할 수 있는 현재 AD 계정 |
| 현재 가능한 행위 | LDAP·AD PowerShell로 AD 객체 조회·변경 또는 Kerberos 서비스 요청 |
| 현재 권한 | 객체별 쓰기·확장·복제 권한 후보 |
| 보유 정보 | 현재 계정 SID, 대상 DN, ACE와 BloodHound edge |
| 네트워크 위치 | DC의 필요한 서비스에 직접 또는 피벗 경유 접근 가능 |
| 목표 | 대상 객체 변경으로 얻는 평문 비밀번호·NT hash·Kerberos ticket·그룹 멤버십을 구분하고 최소 변경으로 실제 권한 확대를 검증 |

## 상태 재평가

- BloodHound edge는 후보이며 PowerView·LDAP 결과와 실제 쓰기 성공을 각각 구분한다.
- 그룹 객체의 `GenericAll`은 그 그룹의 구성원 목록 변경 경로이며, 별도 사용자 객체의 비밀번호 재설정 권한을 자동으로 부여하지 않는다.
- 사용자 비밀번호·그룹 구성원·SPN·`msDS-KeyCredentialLink`의 KeyCredential·GPO를 바꾸기 전 기준값과 정확한 복구 절차를 기록한다.
- 새 평문 비밀번호·NT hash·Kerberos key·ticket을 얻으면 일반 ACL 탐색을 계속하기 전에 그 자료에 연결된 계정의 권한과 원격 접근 범위를 다시 확인한다.
