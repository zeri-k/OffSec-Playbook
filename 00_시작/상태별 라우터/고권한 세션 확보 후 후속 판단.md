# 고권한 세션 확보 후 후속 판단

## 상태 라우터 개요

고권한 신호를 얻으면 먼저 적용 범위를 로컬 호스트·SYSTEM·도메인 객체 권한으로 구분하고, 실제 권한이 충족되는 수집·이동·도메인 기법만 선택한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | Linux·Windows·AD |
| 현재 계정 | root·로컬 관리자·SYSTEM·AD 고권한 계정 중 하나 |
| 현재 가능한 행위 | 고권한 셸·세션에서 명령 실행 또는 AD 객체 조회·변경 |
| 현재 권한 | 그룹명이나 도구 표시가 아니라 실제 실행·접근 권한 확인 필요 |
| 보유 정보 | 권한을 확보한 호스트·계정과 현재 세션 |
| 네트워크 위치 | 로컬 호스트 또는 접근 가능한 도메인 네트워크 |
| 목표 | 권한 범위를 확정하고 다음 상태 변화를 만드는 기법 선택 |

## 상태 재평가

- 로컬 관리자와 Domain Admin, 그룹 멤버십과 DCSync 가능성을 각각 분리한다.
- 고권한 도구 표시보다 실제 파일·프로세스·객체·원격 서비스 권한을 기준으로 한다.
- 새 평문 비밀번호·NT hash·Kerberos key·ticket·개인키, 계정, 세션 또는 네트워크 위치를 얻을 때마다 해당 상태 라우터로 이동한다.
- 목적과 무관한 광범위한 수집 대신 다음 상태 전환에 필요한 기법만 선택한다.
- 실제 고권한이 검증된 상태에서는 일반 플랫폼 셸 라우터보다 이 상태 라우터를 우선하고, AD 객체 권한만 확인된 경우에는 AD 계정 라우터로 범위를 다시 판정한다.
