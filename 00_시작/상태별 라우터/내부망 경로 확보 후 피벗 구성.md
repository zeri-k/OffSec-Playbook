# 내부망 경로 확보 후 피벗 구성

## 상태 라우터 개요

최종 내부망이 직접 보이지 않으면 각 호스트에서 도달 가능한 경계를 먼저 확인하고, 목표에 닿는 가장 짧은 홉까지만 피벗을 구성한 뒤 경로와 최종 클라이언트를 따로 검증한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | 중간 호스트는 Linux 또는 Windows이며 최종 대상 플랫폼은 제한하지 않음 |
| 현재 계정 | 피벗 구성 권한과 최종 서비스 인증 권한을 별도로 판단 |
| 현재 가능한 행위 | 중간 호스트에서 명령 실행 또는 내부 서비스로 트래픽 전달 |
| 현재 권한 | 인터페이스·라우팅 확인과 피벗 프로세스 실행이 가능한 권한 |
| 보유 정보 | 최종 대역 또는 호스트와 중간 호스트 간 연결 경로 |
| 네트워크 위치 | 운영 호스트에서 최종 내부망으로 직접 연결되지 않음 |
| 목표 | 일반 도구가 최종 내부 서비스까지 안정적으로 도달 |

## 상태 재평가

- 각 홉에서 목표 포트 도달성을 비교해 목표에 처음 닿는 호스트를 최종 피벗으로 정한다.
- 새 피벗을 추가할 때마다 네트워크 위치, listener 방향, 사용 protocol과 필요한 권한을 다시 확인한다.
- kernel route·TUN과 sshuttle firewall interception은 여러 일반 client를 CIDR 단위로 사용할 때, SOCKS·포트 포워딩은 proxy를 지원하는 TCP client나 좁은 목적에 우선한다. Metasploit 내부 route는 프레임워크 밖의 일반 client에 자동 적용되지 않는다.
- listener 위치와 연결 방향은 [[피벗과 터널의 연결 경계]]의 제어 연결 시작 주체·진입 listener·최종 connect 세 축으로 다시 확인한다.
- 최종 검증은 단일 TCP 연결 성공과 체인 로그를 먼저 보고, 스캔의 `filtered` 결과만으로 경로 실패를 단정하지 않는다.
- AD/Kerberos가 목표면 IP 도달성 외에 내부 DNS, FQDN과 시간 정합성을 별도 확인한다.
- 실제 서비스 인증·파일 접근·셸을 얻어도 피벗 경로 상태를 버리지 않는다. 다른 대역 도달성이 계속 목표면 이 라우터를, 인증 자료·파일·플랫폼 작업이 목표면 해당 라우터를 선택한다.
