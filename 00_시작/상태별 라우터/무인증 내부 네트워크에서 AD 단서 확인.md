# 무인증 내부 네트워크에서 AD 단서 확인

## 상태 라우터 개요

내부망에 진입했지만 AD 계정이 없으면 수동 관찰과 능동 확인으로 호스트·DC·도메인·사용자 후보를 좁힌 뒤 인증 전 AD 기법으로 연결한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | 아직 불명확하거나 Windows·AD 호스트 후보만 존재 |
| 현재 계정 | 도메인 계정 미확보 |
| 현재 가능한 행위 | 내부망 호스트·서비스 연결 시도, 무인증 정보 조회와 링크 로컬 이름 해석 요청 수동 관찰 |
| 현재 권한 | 네트워크 관찰과 열거 가능 |
| 보유 정보 | CIDR, 인터페이스 또는 일부 IP·hostname 후보 |
| 네트워크 위치 | 내부망 또는 피벗 뒤 도달 가능한 대역 |
| 목표 | DC·도메인·서비스와 인증 전 사용자·정책 단서 확보 |

## 상태 재평가

- ICMP 응답, 포트 열림, AD 서비스 식별, 사용자 존재와 비밀번호 인증 성공을 서로 다른 단계로 기록한다.
- 도메인 계정을 얻은 뒤 AD 객체·권한 관계가 목표면 [[AD Identity 확인 후 도메인 컨텍스트 열거]]를, 인증 자료의 서비스 사용처가 목표면 [[확보한 자격 증명으로 원격 접근 경로 선택]]을 고른다. 호스트·DC 식별이 끝나지 않았다면 이 라우터의 네트워크 단서를 계속 사용한다.
- 새 CIDR이나 피벗 경로를 얻으면 route와 서비스 도달성을 다시 확인한 뒤 같은 흐름을 적용한다.
