# 자식 도메인 장악 후 부모 도메인 경로 선택

## 상태 라우터 개요

같은 포리스트의 자식 도메인 관리자·복제 권한 또는 `krbtgt` key를 확보한 상태에서, 실제 자식 사용자·RID와 부모 trust 조건을 확인해 ExtraSids Golden Ticket으로 부모 리소스 접근이나 대상 계정 DCSync가 가능한지 판단한다. 자식 도메인 관리자 권한, ticket 생성·주입, 부모 서비스의 ticket 수락과 부모 DCSync 성공은 각각 별도 상태로 확인한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | 같은 포리스트에 속한 AD 자식·부모 도메인 |
| 현재 계정 | 자식 도메인 관리자·복제 권한 계정 또는 ticket에 넣을 실제 자식 사용자 |
| 현재 가능한 행위 | 자식 `krbtgt` DCSync, ccache 생성·지정 또는 Windows 세션 ticket 주입, 부모 SMB·DRSUAPI 요청 중 현재 확보한 단계까지 |
| 현재 권한 | 자식 `krbtgt` key 확보 가능 여부와 부모 도메인에서 ExtraSids가 평가되는 trust 조건을 분리 확인 |
| 보유 정보 | 자식·부모 도메인 SID, 실제 자식 사용자·RID, 부모 Enterprise Admins SID와 DC 주소 |
| 네트워크 위치 | 자식·부모 KDC와 부모 DC RPC에 직접 또는 피벗 경유 접근 가능 |
| 목표 | 부모 도메인 대상 계정의 NT hash·Kerberos key 또는 검증된 고권한 세션 확보 |

## 상태 재평가

- 자식 도메인 관리자 credential과 자식 `krbtgt` key는 다른 입력이다. 먼저 DCSync로 key를 얻었는지 확인한다.
- 기본 절차에서 ticket에 표시하는 사용자는 실제 자식 사용자와 RID를 사용하고, 부모 DCSync 대상은 별도 계정으로 구분한다.
- ccache 생성, 자식 KDC 처리, 부모 KDC referral, 부모 DRSUAPI와 대상 credential 출력은 각각 다음 단계의 전제 조건이다.
- 부모 대상 계정 자격 증명을 얻으면 ticket 흐름에서 벗어나 새 자격 증명 상태로 다시 평가한다.
