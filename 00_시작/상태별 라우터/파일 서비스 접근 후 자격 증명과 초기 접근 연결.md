# 파일 서비스 접근 후 자격 증명과 초기 접근 연결

## 상태 라우터 개요

파일 서비스의 목록·읽기·쓰기 권한을 분리하고, 수집한 파일을 자격 증명·실행 경로·내부망 단서로 연결해 실제 상태 변화가 있는 경우만 다음 상태 라우터로 넘긴다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | FTP·SMB·NFS·Rsync·TFTP를 제공하는 환경 |
| 현재 계정 | 익명·Guest·인증 사용자 중 확인된 계정 |
| 현재 가능한 행위 | 공유 목록 조회, 원격 파일 읽기 또는 원격 파일 쓰기 |
| 현재 권한 | 서비스와 경로별 READ·WRITE 권한을 별도 확인 |
| 보유 정보 | 공유·export·module·파일명 또는 인증 정보 |
| 네트워크 위치 | 파일 서비스에 직접 또는 피벗 경유 접근 가능 |
| 목표 | 민감 파일, 사용자명·평문 비밀번호·NT hash·token·개인키, 쓰기 영향 또는 초기 접근 경로 확인 |

| 쓰기 가능한 원격 경로를 root 또는 다른 사용자의 cron 작업이 읽거나 실행하는 단서가 있음 | [[Cron 권한 상승]] | cron 실행 주체의 명령 실행 또는 단순 쓰기 판정 | 셸이면 플랫폼별 셸 상태 라우터, 단순 쓰기는 이 상태 라우터 | 실제 cron 항목·실행 주기·실행 사용자, 대상 파일 소유권과 원래 내용 복구 방법을 확인 |

## 상태 재평가

- 목록 조회, 파일 읽기, 파일 쓰기와 서버 측 실행 가능성을 각각 구분한다.
- 같은 서비스에서도 공유·export·경로마다 권한과 실행 주체가 다를 수 있다.
- 평문 비밀번호·NT hash·API token·개인키를 얻으면 값에 연결된 계정과 대상 서비스를 확인한 뒤 인증 상태 라우터로 이동한다.
- 내부 주소나 추가 대역만 얻은 경우 도달성을 확인하기 전까지 네트워크 접근 확보로 간주하지 않는다.
- 일반 자료는 `자격 증명·계정`, `서비스·실행 경로`, `내부 주소·네트워크`, `추가 단서 없음`으로 먼저 분류한다. 단어 하나가 등장한 사실과 실제 입력으로 사용할 수 있는 최신·완전한 값을 구분한다.
- 자격 증명·셸·고권한·내부망 경로를 얻어도 파일 접근 상태를 버리지 않는다. 파일 내용·쓰기 영향, 인증 자료의 사용처, 플랫폼 실행 환경 또는 다른 대역 도달성 중 현재 목표에 직접 답하는 라우터를 고른다.
