# 확보한 자격 증명으로 원격 접근 경로 선택

## 상태 라우터 개요

확보한 평문 비밀번호·NT hash·Kerberos ticket·SSH 개인키를 그 방식을 지원하는 서비스에만 적용하고, 인증 성공·서비스 권한·세션 확보·관리자 권한을 각각 검증해 다음 상태로 전환한다.

## 적용 조건

| 상태 축 | 조건 |
|---|---|
| 대상 플랫폼 | Linux·Windows·AD·Database·Network 서비스 |
| 현재 계정 | 로컬·도메인·서비스 계정 중 하나이거나 아직 미확인 |
| 현재 가능한 행위 | 대상 인증 서비스에 연결하고 원격 로그인 시도 |
| 현재 권한 | 미확인 상태에서 인증 후 실제 권한을 판정 |
| 보유 정보 | 계정 식별자와 비밀번호·hash·key·ticket 중 하나 |
| 네트워크 위치 | 대상 인증 서비스까지 도달 가능 |
| 목표 | 유효 서비스, 세션 가능 여부와 실제 권한 확정 |

## 상태 재평가

- 로컬 계정과 도메인 계정의 이름 형식·인증 범위를 먼저 구분한다.
- 인증 성공은 대화형 세션이나 관리자 권한을 의미하지 않는다.
- 서비스마다 READ·WRITE·원격 실행·GUI 로그인 권한을 별도로 구분한다.
- 평문 비밀번호·NT hash·Kerberos ticket·개인키 중 보유한 종류, 그 값에 연결된 계정, 인증된 서비스 또는 실제 권한이 바뀌면 다시 분기한다.
- AD 계정, 실제 플랫폼 셸, 원격 파일 접근 또는 고권한이 확인되면 일반 자격 증명 라우터보다 해당 결과 상태 라우터를 우선한다.
