# 상황별 파일 전송

## 플레이북 개요

대상에서 명령을 실행할 수 있고 파일을 저장할 경로가 있다면, 대상 운영체제와 실제 통신 가능한 프로토콜에 맞춰 파일을 반입하거나 회수한 뒤 양쪽 SHA-256이 같은지 확인한다.

## 사용할 때

- shell을 얻었고 열거 도구, payload 또는 결과 파일을 옮겨야 할 때.
- HTTP, SMB, SSH, WinRM, RDP 중 어떤 경로가 열려 있는지 선택해야 할 때.
- 바이너리 손상이나 인코딩 문제를 피해야 할 때.

## 전제 조건

| 조건 | 확인 방법 | 충족 기준 |
|---|---|---|
| 실행 환경 | `uname`, `whoami`, PowerShell 여부 | OS/arch/권한 파악 |
| 네트워크 경로 | `curl`, `wget`, SMB 또는 SSH로 실제 연결 | 파일을 보내는 쪽에서 받는 쪽의 서비스 포트에 연결 가능 |
| 저장 경로 | `/tmp`, `%TEMP%`, writable dir | 파일 생성 가능 |

## 실행

| 관찰한 조건 | 선택 경로 | 연결할 기법·도구 | 완료 기준 |
|---|---|---|---|
| 대상이 공격 호스트의 HTTP listener에 접근 가능 | HTTP(S) 다운로드 | [[curl]], [[powershell]] | 대상 파일 생성 후 크기와 SHA-256 일치 |
| Windows 대상에서 읽을 수 있는 파일을 공격 호스트로 회수해야 함 | HTTP POST 파일 회수 | [[Windows HTTP 파일 회수]] | 공격 호스트의 수신 파일과 원본의 크기·SHA-256 일치 |
| Linux 대상에서 읽을 수 있는 파일을 공격 호스트로 회수해야 함 | HTTP(S) multipart 파일 회수 | [[Linux HTTP 파일 회수]] | 공격 호스트의 수신 파일과 원본의 크기·SHA-256 일치 |
| Windows 대상에서 공격 호스트의 SMB 445/TCP에 연결 가능 | SMB 공유에서 파일 반입 | [[SMB 공유로 Windows 파일 반입]] | 대상 파일 생성과 원본·수신본 SHA-256 일치 |
| 유효한 SSH 계정과 쓰기 경로가 있음 | SCP·SFTP | [[ssh]] | 원격 파일 크기와 hash 일치 |
| WinRM·RDP 세션만 있음 | 세션의 upload·drive 기능 | [[evil-winrm]], [[xfreerdp]] | 세션 경유 저장과 hash 일치 |
| 표준 클라이언트가 없지만 대상이 공격 호스트의 HTTP 포트에 연결할 수 있거나 문자열을 전달할 수 있음 | 운영체제 내장 기능·인코딩을 이용한 반입 | [[제한 환경 파일 반입]] | 복원 파일 hash 일치 |
| 전송은 됐지만 실행이 막힘 | 실행 조건 재평가 | 운영체제별 권한·정책 확인 | 실행 bit·ACL·MOTW·AV 상태 확인 |

1. 현재 OS·arch·identity와 writable 경로를 확인한다.
2. 가장 단순한 단일 경로를 선택하고 listener와 protocol을 맞춘다.
3. 송신 전후 크기와 SHA-256을 비교한다.
4. 반입 성공, 실행 가능 여부와 회수 성공을 서로 다른 결과 상태로 구분한다.

## 관찰과 상태 전환

| 관찰 | 판단 | 결과 상태 | 다음 행동 |
|---|---|---|---|
| 파일이 생성되고 송신본·수신본 hash가 일치함 | 선택한 경로의 전송이 완료됨 | 파일 반입 | 실행 조건을 별도 확인 |
| 대상 파일과 회수 파일 hash가 일치함 | 결과 파일이 변형 없이 회수됨 | 파일 회수 | 필요한 분석만 수행 |
| 수신 서비스에는 요청이 없고 TCP 연결도 실패함 | 선택한 프로토콜, 주소, 포트 또는 통신 방향이 맞지 않음 | 전송 경로 미확보 | 연결 가능한 다른 프로토콜을 고르고 파일 반입이면 [[제한 환경 파일 반입]] 검토 |
| 파일 크기 또는 hash가 다름 | 텍스트 모드, 인코딩, header 또는 중단 전송 문제 | 손상된 파일 | 실행하지 말고 binary-safe 방식으로 재전송 |
| hash는 맞지만 실행이 거부됨 | ACL, 실행 bit, MOTW, 정책 또는 AV 문제 | 파일 반입만 완료 | 실행 권한과 차단 정책을 별도 기법으로 판단 |
| 파일을 읽을 수 없거나 저장할 수 없음 | 현재 세션의 파일 권한 문제 | 네트워크 경로만 확보 | writable·readable 경로와 현재 identity 재확인 |

## 확인할 출력과 권한

| 확인 지점 | 확인할 출력 | 권한 판단 |
|---|---|---|
| 현재 상태 | 운영체제·CPU 아키텍처, `whoami`·`id`, 저장 경로 ACL | 실행 가능한 전송 도구와 현재 계정이 파일을 쓸 수 있는 경로 확인 |
| listener·protocol | 요청 로그, SMB·SSH·WinRM·RDP 연결 성공 | 네트워크 경로와 파일 권한을 구분 |
| 무결성 | 양쪽 파일 크기와 SHA-256 일치 | 전송 완료를 실행 결과로 대신하지 않음 |
| 실행·회수 | 실행 권한·정책, 회수본 hash | 반입, 실행, 회수를 독립 상태로 확정 |
