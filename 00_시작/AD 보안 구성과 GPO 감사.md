# AD 보안 구성과 GPO 감사

## 감사 목적

현재 도메인 계정으로 대상 Active Directory(AD)의 디렉터리와 정책을 읽을 수 있을 때 스냅샷·건강 점검·Group Policy Object(GPO)·인벤토리 도구를 목적별로 고르는 시작 문서다. 각 보고서의 발견 사항은 공격 성공이나 권한 확보가 아니라 재검증할 객체·권한·서비스 후보로 다룬다.

## 사용할 때

- 기본 사용자·그룹 열거를 마친 뒤 도메인 전체의 구성 문제와 누락된 단서를 넓게 확인할 때.
- 특정 시점의 AD 객체·속성·권한을 보존하거나 변경 전후를 비교할 때.
- GPO 설정, 신뢰 관계, 계정 상태, LAPS·BitLocker·Spooler·SMB 같은 보안 점검 결과를 보고서 근거로 정리할 때.

## 전제 조건

| 확인할 것 | 필요한 상태 | 확인 방법 | 미충족 시 다음 확인 |
|---|---|---|---|
| 대상 범위 | 현재 도메인, 전체 포리스트 또는 특정 GPO 중 무엇을 감사할지 결정 | 도메인 FQDN과 필요한 결과 형식 기록 | 목적을 정하지 않은 전체 수집은 나중에 결과 해석이 어려우므로 범위를 먼저 나눔 |
| 실행 위치 | Windows에서 대상 LDAP 389번 또는 ADWS 9389번과 DNS에 접근 가능 | 이름 해석과 대상 포트 연결 확인 | DC에 접근 가능한 내부 호스트 또는 피벗 경로 사용 |
| 현재 계정 | 어느 도메인의 어떤 계정으로 읽는지 확인 | `whoami`와 도메인 인증 결과 확인 | 로컬 계정과 AD 계정, 현재 세션과 별도 입력 credential을 구분 |
| 읽기 범위 | 도구가 사용자·그룹·GPO·trust 등 필요한 객체를 반환 | 좁은 객체 조회로 먼저 확인 | 빈 결과를 설정 부재로 단정하지 않고 계정 권한·대상 서버·프로토콜 확인 |
| 결과 보관 | 스냅샷·HTML·CSV·log의 생성 위치와 수집 시점 기록 | 출력 경로와 파일 존재 확인 | 도구 실행 성공 메시지만으로 보고서 생성을 판정하지 않음 |

## 실행

### 1. 기본 보호 그룹과 관리 범위 확인

```powershell
Import-Module ActiveDirectory
Get-ADGroup -Identity "Protected Users" -Properties Name,Description,Members
```

확인할 출력:

- `Members`에 포함된 계정과 실제 고권한 계정 목록을 비교한다.
- Protected Users 멤버십은 NTLM·delegation·ticket 수명 같은 인증 동작을 제한할 수 있으므로, 멤버십 유무와 실제 인증 실패 원인을 분리한다.

### 2. 목적별 감사 도구 선택

| 필요한 결과 | 사용할 도구 | 확인할 출력 |
|---|---|---|
| AD 객체·속성·권한의 시점별 복사본과 변경 비교 | [[AD Explorer]] | 저장된 snapshot 파일과 비교 결과 |
| 도메인 위험 점수, trust 지도, 호스트·계정·설정 문제 보고서 | [[PingCastle]] | healthcheck·scanner 결과와 HTML 보고서 |
| GPO별 정책 설정과 문제 근거 | [[Group3r]] | GPO·정책 설정·발견 사항으로 구분된 stdout 또는 log |
| 사용자·그룹·컴퓨터·trust·GPO·DNS·LAPS 등 넓은 인벤토리 | [[ADRecon]] | CSV 폴더, GPO XML·HTML과 실행 완료 항목 |
| 객체 관계와 공격 경로 후보 | [[BloodHound]] | edge·path와 수집 시점 |

도구마다 수집 범위와 결과 형식이 다르다. 여러 보고서에서 같은 항목이 반복되어도 각각 독립된 증거로 기록하고 실제 객체 조회나 서비스 접근으로 재검증한다.

| SPN 사용자와 약한 계정 관리 단서 발견 | Kerberoasting 후보 | 대상 서비스 계정 목록 | [[Kerberoasting]]에서 TGS hash 요청과 암호화 형식 확인 |
| Description 또는 SYSVOL에서 비밀값 후보 발견 | 현재 유효성 미확인 자격 증명 후보 | 계정·비밀번호·key 후보 | [[AD 계정 위험 속성과 Description 열거]] 또는 [[SYSVOL GPP 자격 증명 수집]]에서 원본과 인증 여부 확인 |
| ACL 또는 BloodHound edge에서 객체 제어 후보 발견 | 현재 계정의 권한 행사 가능성 | 객체·권한명·상속 범위 후보 | [[AD ACL 권한 열거와 공격 경로 식별]]로 현재 ACL을 직접 확인 |
| GPO 설정 문제만 발견 | 정책 위험 후보이며 GPO 쓰기 권한은 미확정 | GPO·설정·적용 범위 단서 | Group3r 결과와 GPO 링크 범위를 확인하고, 쓰기 ACL이 있을 때만 [[AD GPO 쓰기 권한과 영향 범위 열거]] |
| LAPS·BitLocker·고권한 그룹 정보가 보고서에 표시됨 | 도구가 객체나 설정을 발견함 | 읽기 권한 검증 전 후보 | LAPS 비밀번호가 실제 반환될 때 [[LAPS 비밀번호 읽기 권한과 자격 증명 수집]], 그룹은 직접 멤버십·중첩 확인 |
| Spooler·SMB·LDAP·NTLM 관련 설정 문제 표시 | 서비스별 보호 설정 검증 필요 | 원격 인터페이스·signing·익명 접근 후보 | 해당 서비스 문서와 [[Print Spooler 원격 인터페이스 노출 확인]], [[NTLM Relay 조건 검토]]에서 직접 확인 |
| 스냅샷·HTML·CSV·log 생성 | 감사 자료 생성 성공 | 수집 시점이 기록된 AD 구성 자료 | 중요 발견 사항을 세부 기법으로 재검증하고 보고 근거와 현재 상태를 분리 |

## 확인할 출력과 권한

- 위험 점수, scanner finding, GPO finding과 BloodHound edge는 조사 우선순위이며 실제 공격 성공이나 권한 확보를 뜻하지 않는다.
- 도구가 객체를 나열했다는 사실과 현재 계정이 해당 객체를 변경하거나 비밀 속성을 읽을 수 있다는 사실을 구분한다.
- 스냅샷과 보고서는 수집 시점의 상태다. 세션, 컴퓨터 활성 상태, 그룹 멤버십과 정책 적용 범위는 실행 전에 다시 확인한다.
- Protected Users 같은 강화 설정으로 인증 방식이 제한될 수 있으므로 계정 잠금, 비밀번호 오류, NTLM 차단과 delegation 제한을 같은 실패로 묶지 않는다.
